## 三、逐项设计（正则以原型脚本为唯一权威文本）

### ① F-2 豁免门（procurement breach:195 + NDA breach:145，hardline）

五层机制（全部经原型实跑）：

1. **单一权威命中表**：`_HIT_ALTS` 三元组 → 生产 YAML `hit_alternatives: [{pattern, start_token, neg_sensitive}]`，引擎编译函数派生主命中/禁行起点/豁免终点；正式测试调用生产编译函数
2. **neg_sensitive 字段生效（黄项修复）**：命中表编译为逐 alt 捕获组（lastindex-1=alt 下标），否定检查只作用于 neg_sensitive=True 的命中；旗标接线入测试
3. **否定 = occurrence 前方 6 字符上下文**：受限否定头（不|未）+ 连接字符 [能可予应急再得当为会] + 特例 并未/不视为；双重否定显式不保护
4. **对等豁免链（tempered chain）**：对等量词→【禁行命中起点】→免责事由→【禁行】→命中词；**同句硬边界 = 。\n\r**（阻断①修复：换行是条款的实际边界；分号维持不断链，撤回口径不变）
5. **occurrence 锚定 + 搜索窗口化 ±320**：豁免匹配必须覆盖本次命中区间；生产施工禁止逐命中全文重扫（300 命中压力样例入断言；时间上限断言留生产验收）

### ② payment pass：分句作用域（维持 v1.5）

分句边界 [。；，,;\n\r]；锚定分句头→标的词→给付动作链上禁冒充词；金额兜底同分句作用域。

### ③ term / NDA agreement_term：白名单 + 真分列（阻断②③修复）

- **采购白名单**：合同期限|履行期限|交付期限|供货服务期|供货期|服务期|租赁期限|租期|工期 **+ 生产基线保留组**（`_NUMBER`×日内/天内/个工作日内 → ≤20 字内采购动作；两步判定+票头核对见下）
- **NDA 白名单**：协议期限|(合同|协议)有效期 **+ 生产基线保留组**（协议…自…起…至…止/协议…自签署之日起X年，锚定「协议」）
- **无共享词**（逐词归属见金标）；泛「期限」不再裸收
- **无标签数字期限入口 = 两步判定（v1.9）**：第一步 白名单标签直接通过；第二步 数字期限→采购动作链候选 → **票头核对**（分句内 ××期限 不以采购白名单结尾 → 拒绝）——整改期限为5天内完成验收/索赔期限为10日内完成交付索赔材料/举证期限为7日内完成送货证明提交全拦，同时 30日内完成交付/两个工作日内完成交付/两天内完成送货照常通过
- 四条基线正例入正式回归（外审阻断1指定的 4/4）
- 双向交叉反例入断言：NDA 不收采购词（交付期限）、采购不收 NDA 词（本协议有效期）
- 日期分支：允许期限词 + ≤6 字 + 自…日(起)…至…止；断言匹配区间覆盖完整起止

### ④b 采购期限两步判定的生产接入（外审 v1.9.1 阻断2：白名单匹配器注册表）

**YAML 结构**（term 检查项 pass 节点引用预注册匹配器名，禁止从配置动态导入模块/函数路径）：

```yaml
- id: term
  pass:
    - matcher: procurement_term   # 只允许引用引擎 MATCHERS 注册表中预注册的名字
```

**引擎侧**（app/services/checklist.py）：

```python
MATCHERS = {"procurement_term": match_procurement_term}   # 预注册表，代码内维护
```

**匹配器返回命中对象**（不是裸布尔——一次匹配，四处复用）：

```python
{"matched": bool, "start": int|None, "end": int|None,
 "evidence": str, "hit_type": "whitelist" | "unlabeled_numeric" | "none"}
```

**调用与复用方式**：
- 状态判定：`hit["matched"]` → pass
- quote/hits/证据区间：`hit["start"/"end"/"evidence"]`——`_rule_matches`/`_pass_matches`/`_extract_hits_from_rule`/`_extract_quote_from_rule` 共用这一次匹配结果，不再各自重扫
- `hit_type` 进证据留痕（whitelist=标签路径 / unlabeled_numeric=无标签数字路径），供后续误报来源分析
- **禁止**在 run_checklist 里按 `item.id == "term"` 写特例分支——两步判定全部封装在匹配器内部
- 原型函数 `match_procurement_term`（tools/m65/f12_regex_prototype.py）即生产实现的契约预演；施工后 60 条断言切换为调用生产匹配器，原型降级为设计参考



纯规则工程 + 引擎可选键/新结构（默认行为不变）。四层语义候选通道宪法边界不动；档位唯一来源 = 规则引擎 + 人工决定记录。
