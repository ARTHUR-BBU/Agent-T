## 三、逐项设计

### ① F-2 豁免门（procurement breach:195 + NDA breach:145，均 class: hardline）

**距离口径唯一正式口径（钉 3）：豁免邻域 = ±300 字符（引擎 per-rule `unless_window: 300`）**。金标 ±300 为准；v1.0 的正则 `{0,120}` 作废；引擎现状 ±60 不足以覆盖金标案例（财政部 18.2 句长约 40 字、建设施工通用条款句更长），故加 per-rule 窗口。

**洗白防线（钉 3 反例要求）**：豁免正则把**命中词组本身编进正则尾部**——「对等量词 → 免责事由 → 命中词」三者必须**同句**（句号边界 `[^。]`）依次出现，匹配跨度同时受 ±300 窗口约束：

```
need_attention unless（procurement breach 示例；NDA 同构）:
  # 第一层：否定语境豁免（贴身窗口即够，60 默认窗口内生效）
  - "不免除|不得免除|不视为免除|并未免除|不免责"
  # 第二层：对等豁免门（unless_window: 300；三要素同句）
  - "(任何一方|双方均?|各自|彼此)[^。]{0,150}(不可抗力|情势变更|政府行为|自然灾害|疫情)[^。]{0,80}(不承担违约|无需承担违约|免除违约责任|免除.{0,8}违约|不负违约金义务|不得主张违约金|豁免违约责任|违约责任由.{0,10}自行承担)"
```

- 命中词三要素同句保证：相邻**独立**的单方免责句（跨句号/跨条款）不含对等量词+免责事由同句链 → 不被豁免
- 分号/换行边界：`[^。]` 只认句号为界；分号「；」与换行**不**重置豁免链（金标口径：同句 = 句号内），对抗测试显式覆盖「分号连接的相邻单方免责」反例
- 施工时变异验证校准跨度参数（150/80 允许 100~200/40~120 微调），红→绿双向实证
- note 文案、hardline 定级、need_attention 主模式**全部不动**

### ② payment/term pass 语义域（含反误报护栏，钉 5）

**payment pass**（procurement:168-172）新增（现有四条保留）：

```
# 语义域 A：标的词 ∧ 给付动作同句；句内含违约/赔偿语境则整句不作数（负向护栏前置）
- "(?![^。]{0,60}违约金)(?![^。]{0,60}赔偿)(价款|货款|报酬|服务费用?|租金|对价|合同总价|合同金额|结算)[^。]{0,40}(支付|付款|付清|结清|支付给)"
- "(?![^。]{0,60}违约金)(支付|付款|付清|结清|支付给)[^。]{0,40}(价款|货款|报酬|服务费用?|租金|对价|合同总价|合同金额|结算)"
# 语义域 B：金额兜底（不单独成立——仅价款语境词与金额同句，或给付动作与金额同句）
- "((价款|总价|合同金额|费用)[^。]{0,20}(人民币|\\d+\\s?元))|((支付|付款|付清|结清)[^。]{0,30}(人民币|\\d+\\s?元))"
```

反误报样例（必须不通过 payment，进对抗断言）：「违约金按合同总价的 10% 支付」（总价+支付被负向护栏拦截）、「违约金金额为 5 万元」、「赔偿总额以合同总价为限」（责任上限）、「注册资本人民币 100 万元」。金标正样例：「甲方收到发票后＿个工作日内将上月采购款支付给乙方」→ 不得未找到。

**term pass**（procurement:181-187）新增（现有交付口径四条保留）：

```
- "合同期限|履行期限|交付期限|供货服务期|供货期|服务期|租赁期限|租期|工期|(合同|协议)有效期"
- "自[^。]{0,15}日起?[^。]{0,15}至[^。]{0,15}止"
```

- **bare「有效期」不收**（钉 5）：「产品有效期不少于 18 个月」→ 不得通过 term（对抗断言）；只认「合同/协议有效期」前缀式
- NDA `agreement_term` pass 同步加同构语义域（该清单现行 pass 词表施工时核对，缺失即补「协议期限|保密期限|(合同|协议)有效期|有效期至」）

### ③ 签署等价组（三清单 signature：procurement:348 / lease:411 / nda:287）

procurement/nda unless 补两行，lease 已有等价组（15 份实证组）补同两行：

```
- "法定代表人[:：]"
- "授权代表[:：]|委托代理人[:：]"
```

**主体介绍反例防线（钉 4）**：等价组生效依赖 unless 的**同现窗口**（落款行模式必须出现在盖章命中 ±60 内）——「甲方：某公司，法定代表人：张三，住所地：…」出现在主体条款（第一条），距签署页盖章栏通常远超 60 字符 → 不会误放行。反例断言：

- 「全文只有主体介绍段的『法定代表人：张三』+ 无任何盖章字样」→ 不得通过（无盖章命中，missing_as 维持）
- 「主体条款含『法定代表人：』且距全部盖章字样 >60 字符 + 盖章孤行无自然人落款」→ 维持需关注
- 「盖章栏 ±60 内有『法定代表人：』落款行」→ 通过（金标正例）

边界不松：纯盖章孤行 → 需关注；全无 → missing_as 维持。「空白模板」报告层旗标挂第二批。

## 四、权力边界声明（本批不新增任何 LLM 权力）

本批是**纯规则工程**（YAML 词表/正则 + 引擎 per-rule unless_window 一个可选键），不触碰 LLM 层。四层语义候选通道边界维持宪法口径：model_review 分类≠裁判、blind_spot 候选需人工确认、quality 参谋不计分、objection 永不改当次档位。**档位唯一来源 = 规则引擎 + 人工决定记录（2c）；LLM 只产候选与解释，无档位权力。**
