# B7-5a 施工卡：AI 发现流水线合并（观察+核验→统一发现→确认后可改写可追问→入报告）

> 老板 2026-11-04/05 试用反馈立项（含拍板：a→b 顺序，a+b 全部完成）。
> 本卡=B7-5a（流水线合并+报告收录，后端为主+前端小改）；B7-5b（桌面
> 双栏重布局+问清楚对话框化，阳仔线框先行）另卡。
> 费用：开发全程零 LLM；启用新功能后的费用走既有线上交互闸。

## 一、目标（一句话）

把「AI 观察」和「需你确认」两条流水线合并为**一条「AI 发现」流水线**：
**发现 → 自动取证核对 → 人拍板（确认/争议）→ 确认项可生成修改建议、
可追问 → 全部落入 Word 报告**。老板原话：观察不就是发现问题，然后你
去核对，再由人确认吗？

## 二、核心架构决策（施工前拍板项，已定）

**确认后成为检查项，复用全部既有机制——不另起平行流水线。**

用户对一条发现点「确认」后，系统将该发现**物化为一张检查项**追加进
审查单 items（`tag_source="ai_finding"`，名称带【AI 发现】前缀），
此后三卡（生成/选定/牵连）、追问、报告逐条明细**全部复用 B7-1~B7-4
既有机械**，零平行实现。理由：

- 修改建议/牵连/追问的资格判定、额度闸、安全过滤全部现成
- 报告端 AI 发现条目天然进「逐条明细」+确认记录进「人工决定与确认」，
  两节合并口径自然成立
- 争议/未确认的发现**不物化**（只留记录，不可改写）——确认是人拍板
  的闸门，闸门后才给修改能力，与铁律「确认是核验不是采纳」一致

## 三、统一状态机

| 阶段 | 事实类发现（缺条款/写矛盾等） | 观点类发现（对您的影响等） |
|---|---|---|
| 发现 | AI 观察维度产出 / 核验疑点产出 | AI 观察影响维度产出 |
| 核对 | 自动取证核对（附证据，verified/unverified） | 标注「观点，无核对」（无原文可核） |
| 拍板 | 待确认 → 确认 / 争议 | 待查看 → 已阅 / 争议 |
| 物化 | 确认 → **生成 AI 发现检查项**（可改写/可追问/入明细） | 不物化（不可改写） |
| 报告 | 明细+确认记录 | 单列「AI 观点」小节 |

数据来源合并：quality 观察与 verify 疑点**产出侧不动**（各查各的），
新增聚合视图 ai_findings(review) 统一呈现；确认/争议状态持久化到
新表 ai_finding_status（review_id, finding_key 唯一）。

**finding_key 规则（codex #173 复批 P1-1：稳定唯一）**：
- 观察类：`obs:{维度}:{sha1(title)[:12]}`
- 疑点类：有 claim_id 用 `ver:{claim_id}`；**无 claim_id 用
  `ver:{sha1(title+quote)[:12]}`**（已核代码：verify.py 的 claim_id
  允许为空串，备用键必须有）

**观察↔疑点去重（codex #173 复批 P1-2）**：已核代码——核验确认问题
**就是从 quality.observations 派生的**（verify.py 遍历 observations
造「请确认」问题，title 逐字沿用；另有 pack_verify 独立疑点源）。
派生关系的问题与观察**合并为一条发现**：共用核对证据/确认状态/
物化检查项（实现：派生时在问题行打 obs_key 标注，合并按 obs_key）；
pack_verify 独立疑点单独成条。**同一发现只呈现一次**（demo-1 实测：
vq01-08 逐字来自观察 1-8，合并后 12 条观察+独立疑点只显示 12 条）。

**规则清单↔AI 发现跨源呈现（老板 2026-11-04 问，实测数据支撑）**：
demo-1 三源重复度实测——观察↔疑点 8/12 完全包含（派生）；规则 4 条
需关注中 1 条与观察近重复（主体信息）、1 条角度互补（背靠背条款判
vs 付款期冲突）、2 条不同角度（定金方向/并用不明）、1 条各自独立
（适用法律）。呈现口径：**规则条目保持判定主位不删不藏；AI 发现与
规则同主题时标注「与规则结论一致（互相印证）」**（双通道印证是
价值不是噪音——文字+颜色双通道哲学沿例）；角度互补各自保留。
确认动作触发物化。

## 四、范围（B7-5a）

1. **聚合视图**：ai_findings(review) 合并观察+疑点为统一发现清单
   （含来源标记、核对证据、状态）；前端「AI 观察」「需你确认」两面板
   替换为单一「AI 发现」面板（现单列布局下先可用；重布局归 B7-5b）
2. **物化**：确认 → 追加 AI 发现检查项（tag_source="ai_finding"，
   带原文引句/坐标——观察自带 quote；疑点带核对证据坐标；无坐标的
   疑点不可物化，如实提示）
   **反悔处理（codex #173 复批 P1-3）**：确认后改判争议 → 物化检查项
   **停用**（生成/追问入口对该 id 拒答），**历史留痕保留**（明细条目
   保留并标注「已争议撤回」，不再可操作），报告确认记录更新为当前
   状态。验收用例：确认→物化→生成可用→改争议→生成/追问被拒→
   报告标注「已争议撤回」→ 再次确认可复活（状态机闭环）
3. **可改写**：AI 发现检查项自动获得三卡（复用）；**牵连词族派生**：
   引句中的高频实体词派生临时词族（词族配置无此 id 时），uncovered
   如实标注——牵连质量如实声明为「尽力检索」
4. **可追问**：askable 范围扩展至 tag_source="ai_finding" 的需关注项
5. **报告**：物化条目进逐条明细（【AI 发现】前缀）；确认/争议记录进
   「人工决定与确认」；**报告范围说明文案改为「含规则核查、AI 发现
   与确认记录、参考评分与补盲」**（原「不含 AI 观察及追问」作废）
6. **"再审本条"**：保留但降级为已确认条目的次级动作（图标级），
   B7-5b 重布局时再评估去留
7. **兼容**：历史旧记录（无 ai_finding 数据）按现状渲染，零迁移

## 六、测试清单（关键项）

- 聚合视图：观察+疑点合并、状态机各态、finding_key 稳定性
- 物化：确认→检查项追加（tag_source 正确、quote/坐标随行）；争议/
  未确认→不物化；重复确认幂等（不重复物化）
- 物化后全链：生成（额度闸生效）→选定→牵连（派生词族+uncovered
  如实）→追问 askable→GET state 恢复
- 报告：物化条目进明细、确认记录进决定节、范围文案更新、旧记录
  报告字节不受影响
- 入口级：AI 发现检查项的生成/牵连同样受限未覆盖门禁不撤
- finding_key：无 claim_id 疑点的备用键稳定性（两次聚合同键）
- 去重：观察与其派生问题合并为一条（demo-1 形态：vq01-08 并入）
- 跨源标注：与规则同主题的发现带互相印证标注
- 反悔闭环：确认→物化→改争议→拒答→报告标注→再确认复活
