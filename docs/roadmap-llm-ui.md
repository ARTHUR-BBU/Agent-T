# Agent-T 深化路线图：LLM 定位 + UI 升级（v1.0，2026-09-09）

> 输入：Codex 架构建议 + ChatGPT 体验建议 + 开发狗审核 + 法务老钱裁决书 + 阳仔 UI 提案。
> 本文档是路线图的唯一权威版本；各阶段实施前另出专项 spec。

## 一、LLM 定位宪章（铁律修订 v2，老钱裁决直接 adopt）

**规则三分法（簇级，元数据 `class:` 标注，未标默认 heuristic）**：

| 类别 | 定义 | 例 | LLM 上限 |
|---|---|---|---|
| hardline 业务硬约束 | 命中即失衡/违法/脱钩，漏报代价不可逆 | 押金没收脱钩（民法典585）、知产归接收方、签收即验收 | **只解释**，永不接受异议 |
| existence 事实存在性 | 「有没有写 X」，价值中立二值 | 期限、管辖、保密条款有无 | 可提**漏报异议**（等价写法被词表漏掉） |
| heuristic 文字筛查线索 | 命中词与风险隔着语境推理 | 全款付清、单方调价 | 可提**误报异议**（需关注→通过方向） |

**铁律修订五条**（替换「LLM 永不改写规则档位」）：
1. 存在性档位（通过/需关注/未找到/本类不适用）唯由规则引擎签发，任何路径不得由 LLM 输出或覆写。
2. LLM 产出仅存在于两层：**解释层**（note 扩写、法条依据、质量层分析）与**异议层**（仅 heuristic 误报方向、existence 漏报方向）。
3. 异议永不直接变更档位；档位变更唯一通道 = 版本化规则修订 + 金标/回放零错杀 + 回归哈希。
4. hardline 簇不接受异议。
5. 质量层条目必须带原文引用与「待人工确认」标记，不计入评分卡。

**明确否决**：ChatGPT「LLM 直接承担语义判断出档位」——档位不可复现会作废 M3.5/M4/回放校准全部工程资产；「裁定要有可撤销的载体：规则错了修规则，LLM 错了修的是概率」。

## 三、纪律与流程

- 每阶段合并前：全量 mock 绿 + 回放集对比（误报/漏报不退步）+ 双门禁 + 用户确认，回归声明附哈希。
- 铁律 v2 已生效（本文档第一节）；后续任何 LLM 新场景过「四问准入面试」（失败降级答案/能否变档位/可溯源/是否在请求路径）。
- 引框架判据（阳仔五条）挂入前端 README，触发才立项 Preact+htm，不进打包器。

## 四、UI 执行规格补充（ChatGPT/Astra 审核后两案归一，2026-09-09）

阳仔提案为基底，ChatGPT UI 建议三色审核后并入以下裁决：

1. **移动端问题详情 = 独立页面**（覆盖阳仔的行内展开方案）：阅读顺序固定为
   摘要→原文依据→影响说明→修改建议→追问输入；返回保留清单位置/筛选/滚动。
   桌面端保留行内面板。原生 JS 视图切换 + hash 路由实现，不引框架。
2. **追问页并入详情页**：原文仍钉顶部、单次问答非气泡流（阳仔底线保留），
   省掉「问清楚一点」独立跳转。
3. **术语人话化**（九哥裁定后执行）：来源徽章「规则→系统核查」「补盲→待核实
   发现」；「需关注」等四态档位名与「需人工确认」声明是红线语义，不动。
4. **每条清单项露出一句话摘要**（note 首句），不再只有「名称+档位」。
5. **新增设计禁令**：不伪造「高/中/低」风险等级；风险提示必须文字+颜色双通道
   （色弱可用）；隐私文案去内部术语，改用户可理解表述+展开详情。
6. 上传页立场输入一期落位（阶段 1 能力），ChatGPT「以后再加」不采。

其余维持阳仔方案：IA 重排顺序、评分卡折叠、dialog 化、token 收编、移动端
480px 单断点、五组件重做、hash 恢复（阶段 0 首位）、引框架判据五条。

## 五、明确不做

多 AI 互辩；LLM 出档位；评分投入加深（保持配角）；报告 docx 引入 LLM 生成内容（质量层只在 Web 展示层）；营销化 UI；深色模式。
