## 0. 一句话讲给老板 + 设计立场

改版前的工作台像个**只认上一页的便签本**：你在清单里点了另一条，本子上贴的还是前一条的说明和原文——聊着聊着忘了自己在聊哪条。改版后它是一本**跟着手指走的笔记本**：手指点到哪条清单，封面标题、说明便签、聊天对象立刻翻到那一页，不用再按一下「问清楚」当书签。「看看怎么补」则是给「未找到」这种死条目配的一支**铅笔**：AI 先帮你翻全本合同确认真没写，再递一张打了留空线的示范草稿——笔递给你，字还是你自己签。

设计立场（延续整壳三原则）：
- **选中即同步**是唯一主轴：任何区块的标题、目标、过滤范围都以「当前选中条目」这一个状态源推导，不设第二个真相
- 补写是**克制的能力**：入口只在未找到条目详情里出现一张卡，不用琥珀不用红——「缺东西」不等于「出事了」；草稿明示留空、明示「示范文本，非法律意见」
- 铁律不破：选用不自动改合同、不改档位；界面只呈现规则引擎结论，草稿卡是「人的拍板通道」的纸，不是第二个判定器

## 1. B7-6d：对话工作台改版

### 1.1 版面总图（codex 草案细化，桌面 ≥1024）

宿主不变：仍在 col-side 便签本下半段（#item-detail 之下）；<1024 走既有 matchMedia 搬迁（清单扩为 detail+workbench 双节点）。改的是 **#ask-workbench 内部**的分区与顺序：

```
┌ #ask-workbench ────────────────────────────────┐
│ ① #wb-head（新增包裹层）                         │
│   正在讨论：付款期限前后不一致                    │  ← #ask-title（沿用，去 hidden，
│   [需关注]                                       │    常驻显示；档位 tag 复用既有）
│ ② #wb-status（沿用 #ask-status-line，原位）       │  ← 处理中/失败文案行
│ ③ #wb-context-fold（新增，<details> 默认收起）    │
│   ▸ 相关说明与原文                               │  ← <summary>
│   ┌ 收起内：#ask-note-card（沿用整卡）───────┐   │
│   │  说明 #ask-context / 条款锚点 #ask-clause │   │  ← 两卡整卡平移进折叠体，
│   │  #ask-quote-card（沿用整卡）              │   │    id/渲染函数一概不动
│   │  原文 #ask-quote（黄底命中词）            │   │
│   └──────────────────────────────────────┘   │
│ ④ #wb-history（新增，<details> 默认收起）        │
│   ⌄ 历史对话（3轮）                              │  ← <summary>，轮数实时
│   查看范围：[本疑点] [本合同全部]                 │  ← #wb-scope（新增，pill 双选）
│   ┌ 收起内：#ask-thread（沿用，可滚动）──────┐   │
│   │ 🙋 关于：付款条件  违约金30%合理吗？      │   │  ← 每轮头顶 caption 标签
│   │ 🤖 四段式答案…                           │   │    （沿用整壳 §3.3 规则）
│   │ ┄ 本疑点无轮次时：空态一行 ┄              │   │
│   └──────────────────────────────────────┘   │
│ ⑤ #ask-interact（沿用整卡）                      │
│   #ask-answer（当前问答，四段式）                │  ← 已在输入上方（480px order:-1
│   #ask-followups-wrap（chips）                   │    先例），本批全断点统一此序
│   #ask-pending（断线恢复提示）                    │
│   [ #ask-input ]  [ #btn-ask 发送 ]              │
│   #ask-error                                     │
└────────────────────────────────────────────────┘
（#rev-cards-ask 移动端三卡挂载点：原位保留，不动）
```

要点：
- **DOM 顺序变化只有两处**：ask-title 从 hidden 孤行升级为 #wb-head 常驻头；ask-note-card/ask-quote-card 两整卡从明面收进 #wb-context-fold。其余节点全部原 id 原位
- 说明与原文折叠体里**只渲染本疑点内容**——切换选中时两卡内容随 selectItem 同步刷新，没有「上一条的残留」（这正是本次改版要杀的缺口）
- ask-answer 从「仅 480px 提到输入上方」改为**全断点统一在输入上方**——桌面也先看到当前问答再看到输入框，和 codex 草案「当前问答 → 输入」的读序一致

### 1.2 区块明细（每块：id / 默认态 / e2e 锚点）

**① 工作台头 #wb-head**（新增包裹 div，包住既有 #ask-title + 新增档位 tag 位）
- 文案：`正在讨论：{条目标题}`；旁边复用既有档位 tag 样式（需关注=琥珀、未找到=中性）——档位语言不重画
- 未选中条目时整块显示占位 caption「先从清单选一条来讨论」（此时输入禁用，见 ⑤）
- 默认态：常驻展开；e2e 锚点 `#wb-head` 存在 + `#ask-title` 文本含选中条目名
- **同步规则（拍板 1）**：selectItem() 在更新 #item-detail 的同一笔逻辑里，同步写 #ask-title 文本——单一状态源，不设独立刷新路径

**③ 说明与原文折叠 #wb-context-fold**（新增）
- `<details class="wb-fold">` + `<summary>相关说明与原文 ▸</summary>`，零 JS
- 默认态：**收起**（拍板 2）；用户手动展开后，同一条目选中期内保持展开（details 原生行为即如此，不额外记状态）；**切换条目时回到收起**——新疑点的说明默认不摊开，避免旧展开状态盖住新内容的「第一眼」
- 收起内节点：#ask-note-card、#ask-quote-card 两整卡平移，id 不动
- e2e 锚点：`details.wb-fold` 的 open 属性断言 + 折叠体内 `#ask-context` 文本随选中切换变化

**④ 历史对话区 #wb-history**（新增包裹）
- `<details class="wb-fold">` + `<summary>历史对话（{N}轮）⌄</summary>`
- 默认态：**收起**（codex 草案「展开后可滚动」）；点击发送新问题或收到新回答时自动展开一次（用户需要看到回答落进哪一格）；0 轮时整区隐藏（不显示「历史对话（0轮）」的空壳，克制）
- 展开态内部限高滚动（约 5 轮高度），滚动体是 #ask-thread 自身——sticky 自滚动纪律不变
- **范围切换 #wb-scope**（新增）：折叠体内顶部一行，两枚 pill 单选「本疑点 / 本合同全部」，默认**本疑点**（拍板 3）；选中态复用 `--color-selected-bg` + `--radius-pill`；e2e 锚点 `#wb-scope [data-scope="item|all"][aria-pressed]`
- 过滤语义：范围只是**视图过滤器**，后台永远是同一份合同对话记录（拍板 3 后半句）——切范围不发请求、不重排存储，纯前端过滤
- 每轮「关于：××」caption 标签沿用整壳 §3.3 规格；范围=本合同全部时，相邻轮次条目变化处渲染既有「切换分隔线」（主批已拍板的形态，直接复用）；范围=本疑点时不加分隔线（全是同一条，线是噪音）
- e2e 锚点：`#ask-thread[data-scope]` + 轮次节点 `[data-turn-item="{key}"]`；断言「本疑点范围只含该 key 的轮次」「全部范围轮次总数=持久化返回数」

### 1.3 选中同步状态机（拍板 1+4 合并写死）

```
状态源：state.selectedItem（唯一）
  ├─ 变化 ⇒ ① #ask-title 重写
  ├─      ⇒ ② #wb-context-fold 内容重写 + details 回到收起
  ├─      ⇒ ③ #wb-scope 回到「本疑点」默认值 + #ask-thread 按新 key 过滤
  ├─      ⇒ ④ 草稿缓冲：旧 key 的输入框内容存入 draftMap[旧key]；
  │           新 key 有存草稿则回填，没有则清空（拍板 4「草稿保留」=按条目各留各的）
  └─      ⇒ ⑤ 处理中的旧回答**不动**：轮次已带 data-turn-item=旧key，
              归档照常（三-补2 已写死的甲归甲），只是从新 key 的「本疑点」视图里消失，
              切回旧 key 或切「本合同全部」即见
```
- 禁发态不放宽：未选中条目 ⇒ #ask-input disabled + #wb-head 占位文案；askable 判据沿用（三-补1 口径），6c 窄开见 §2.3
- 既有判废机制（askReqSeq/REV_STATE）零改动——本节全是视图层过滤与文案同步

### 1.4 移动端（<1024，含 <480）

- #ask-workbench 走既有搬迁机制落到 col-main 三卡之后，内部 ①-⑤ 结构**与桌面完全一致**（同一套 DOM，这正是整壳统一的红利）
- 折叠默认态同桌面：说明原文收起、历史收起；<480 无任何专属变体
- 触控目标：summary 行、scope pill、发送按钮均 ≥44px（既有卡片区先例）

## 2. B7-6c：「看看怎么补」入口卡

### 2.1 入口位置与形态

**位置：#item-detail 内、#detail-quote 之后、#rev-cards 之前。** 新增一节：

```
│ #detail-quote（原文，黄底）        │  ← 沿用
│ ┌ #draft-entry-card（新增）─────┐ │
│ │ 这条在合同里没有找到对应内容。  │ │  ← caption 灰，陈述事实不惊吓
│ │ 可以让 AI 先查查是否写在别处，  │ │
│ │ 确实缺失再给一份补充草稿。      │ │
│ │ [ 看看怎么补 → ]               │ │  ← 复用既有 link 按钮样式
│ └───────────────────────────────┘ │
│ #rev-cards（三卡，沿用）           │
│ #detail-actions（问清楚一点 →）    │  ← 沿用
```

形态要点：
- 一张中性卡：白底、既有卡片边框体系、**不用琥珀不用红**——「未找到」的档位 tag 保持中性，补写入口不追加情绪色（克制红线：缺东西≠出事）
- 只在**档位=未找到且非补盲**的条目详情里渲染；其他档位整卡不出现（不是每个详情都摆一支铅笔）
- 左栏下区不放入口——一处入口一个语义，入口跟着详情走
- e2e 锚点：`#draft-entry-card[data-state="idle|checking|elsewhere|draft|error"]`、按钮 `#draft-entry-btn`

### 2.2 三步的状态机与界面呈现

```
[idle] --点「看看怎么补」--> [checking]
[checking] --AI 查全合同--> ├ [elsewhere] 相关内容写在别处
                           ├ [draft]     确实缺失 → 草稿卡
                           └ [error]     查询失败（留重试）
```

**[checking] 等待态**：卡片原位文案替换为「正在结合整份合同检查：相关内容是否写在别处、是否已有替代安排……」——真实进度文案，无 spinner 无假百分比（既有红线）；此间按钮置灰防重复点。e2e：`data-state="checking"`

**[elsewhere]「写在别处」结果态**（流程①的否定答案，同样是有用结果）：
- 文案：「这条内容在合同其他位置有体现」，下列出落点：条款锚点（复用 #detail-clause 的呈现样式）+「看原文」跳转（复用既有 evidence-jump 链路）
- 卡片底部留一枚「仍然觉得缺 → 给我草稿」次级链接，尊重用户的独立判断（AI 说写了、用户觉得写得不够，路径不断）
- e2e：`data-state="elsewhere"` + 落点条款锚点可断言

**[draft] 草稿卡**（流程②产物，替换 #draft-entry-card 内容）：

```
┌ #draft-card（新增）───────────────────────────┐
│ 补充草稿 · 关于：{条目名}          [caption]   │
│ ┌ #draft-body ─────────────────────────────┐ │
│ │ 草稿正文（示范文本，非法律意见——常驻灰字） │ │
│ │ 缺金额处：「____（待填写：金额）」          │ │  ← #draft-blank 行内留空占位
│ │ 缺期限处：「____（待填写：期限）」          │ │    底色用 --color-aside-bg
│ └──────────────────────────────────────────┘ │
│ 常见位置参考：#draft-place（一句话+条款锚点）   │
│ 关联条款：#draft-links（既有 tag 体系小标签）   │
│ [继续讨论] [标记选用] [忽略]                   │
└──────────────────────────────────────────────┘
```

- 草稿正文字段布局从上到下=**正文→位置→关联**：先读内容再知道放哪最后看邻居，是补条款的自然读序
- 留空占位（#draft-blank）：统一样式「____（待填写：××）」，底色 `--color-aside-bg`（既有 token，零新色）——**AI 不编造金额/期限，空就是空，而且空得看得见**（拍板 2 的「不替用户编造」落到视觉上）
- e2e：`#draft-card[data-state="draft"]`、`#draft-body` 非空、`#draft-blank` 数量与后端返回一致
- 草稿头部固定声明（老钱定稿口径）：「AI 生成的示范文本，仅供参考，不构成法律意见。采用前请专业人士复核，并与您的实际交易情况核对。」

**流程③ 用户处置（三个动作，状态各归各）**：
- **继续讨论** → 见 2.3，进共享对话流
- **标记选用** → 卡顶加一枚「已标记选用」caption + 说明（老钱定稿）：「您声明已补入，本系统未验证此修改；建议重新提交审查以确认。」——**不自动改合同、不把「未找到」改成「通过」是铁律**（拍板 3）；选用态记在该条目上，刷新恢复。e2e：`#draft-card[data-adopted="true"]` + 清单里该条目档位 tag 仍为未找到
- **忽略** → 折回 [idle] 态（用户反悔可再点，不锁死）

**[error] 态**：行内 #draft-error（复用既有 .error 样式）+「重试」链接；失败不静默、不留半截卡。e2e：`data-state="error"` 可见

### 2.3 与对话工作台的关系（拍板倾向落定：进共享流）

- 点草稿卡「继续讨论」⇒ 滚动聚焦 #ask-input，自动带上该未找到条目为讨论对象；补写轮次进**同一份**合同对话记录，turn.item_id=该条目，每轮标签在「关于：××」后追加来源标记「· 补写」
- **门禁窄开**（纪律，老钱已确认）：未找到条目的发送资格**只在草稿卡生成后才开放**——从清单直接点未找到条目仍不可发（与三-补1 口径一致）；服务端同口径校验（remediation 存在才放行），前后端两道闸
- 范围过滤天然覆盖：本疑点视图=该条目全部轮次（含补写轮）；「本合同全部」视图里补写轮靠「关于：×× · 补写」标签自明出身——不建第二套对话流
- 报告收录沿用主批对话章节机制，补写轮随章节自然带入（来源标注已含），章节编号条件式顺延规则不变；补写草稿全文+选用状态留痕进报告（老钱 2.3 裁定）
- 「问清楚一点 →」按钮在未找到条目上**不出现**（现状即如此，保持）——未找到的对话入口只有补写这一条窄门，避免两个入口抢一个语义

### 2.4 移动端（<1024）

- #draft-entry-card / #draft-card 跟随 #item-detail 在 col-main 流内行内展开，无独立页无弹窗
- 折叠默认态：idle 卡常驻（它本身就是收起形态，一行按钮）；draft 卡生成后常驻展开（草稿是用户主动要的，再折叠就是藏东西）
- 「继续讨论」跳转后工作台在详情下方紧邻位置，单列流天然可达，无需锚点
