# B7-3a 三卡线框（最小形态，阳仔 v1，2026-11-01）

> 依据：spec-b7-3-ui-report.md v3（§一/§四A/§五A/§九）+ design-tokens.md 视觉标准 v0.1。
> 范围：仅 B7-3a 页面三卡。报告章节（B7-3b）不在本线框内，仅预留入口提示位（见 §7）。
> 铁律：所有态只渲染 `GET .../revision/state` 真实返回字段，不发明字段；刷新只调这一个 GET，绝不自动触发 AI 调用。

## 0. 挂载点与视觉基调

- 挂载：`app/static/index.html` 的 `#item-detail` 内部，`#detail-quote` 之后、`#detail-actions`（问清楚一点）之前。三卡按「改写建议卡 → 选定卡 → 牵连检查卡」顺序垂直排列。
- 出现条件（施工卡 §一.1）：仅「需关注」且有原文摘句（item.quote 存在）的检查项显示三卡入口；其余项整块不渲染。
- 懒加载：点开检查项详情时调一次 `GET /api/review/{rid}/items/{iid}/revision/state` 恢复状态（纯读库、零 AI、零扣额）。切换检查项即重新拉取该项的 state。
- 视觉：沿用「AI 建议参考层」既有先例（阶段 2.1 质量层）——容器 `1.5px dashed var(--color-divider)`、底色 `var(--color-aside-bg)`，徽章/chip 走 `--color-text-secondary/tertiary` 中性灰。零新 token、零新色。
- 信任基调：所有降级/失败/耗尽态用次文案灰（`--color-text-secondary`）+ 说明性措辞，禁红色告警；只有按钮可用态用 `--color-accent`。

## 1. 卡一：改写建议卡

```
┌──────────────────────────────────────────────┐
│ ▤ AI 修改建议            [参考层虚线容器]      │
│                                              │
│ 〔态A 初始未生成〕                             │
│   ( 生成修改建议 )        ← 主按钮 --btn-height │
│   本合同还可生成 3 次      ← caption，来自 remaining.revision │
│                                              │
│ 〔态B 正常态：最新一批展开〕                    │
│   「最新生成 · 10月31日 14:20」  ← drafts[0].created_at │
│   ┌ 方案一 · 稳妥 ───────────────────┐        │
│   │ 修订文本…          ← versions[i].text │
│   │ 适用说明…          ← versions[i].note │
│   │ ( 选定这一版 )      ← 小按钮，进入卡二  │
│   └────────────────────────────────┘        │
│   ┌ 方案二 · 平衡 ─┐  ┌ 方案三 · 进取 ─┐      │
│   │ （同上结构）    │  │ （同上结构）    │      │
│   三版共同理由…           ← rationale │
│   事实假设：…             ← assumptions[] 逐条 │
│   非法律意见声明…         ← declaration │
│                                              │
│ 〔态C 加载失败 degraded〕                      │
│   修改建议这次没有生成成功，已为您记录在案。      ← drafts[last].status==="degraded" │
│   ( 再试一次 )  ← 仅 remaining.revision>0 时出现；绝不自动重试 │
│                                              │
│ 〔态D 预算耗尽〕                               │
│   ( 生成修改建议 ) 置灰不可点                   │
│   本合同的生成次数已用完。   ← remaining.revision===0 │
│                                              │
│ 〔态E 刷新恢复（只读渲染）〕                    │
│   「最新生成 · …」 批次默认展开；               │
│   更早批次折叠为一行：「此前生成 · 时间」        │
│   含选定版的批次标注 ●「您已从这批选定」        ← drafts[i].is_selected │
│   历史批次只读展示，按钮不消失但需显式点按才触发新调用 │
└──────────────────────────────────────────────┘
```

字段映射：批次头=drafts[].created_at；版本块=versions[]（stance 作「方案一·稳妥」序号标签）；共同理由=rationale；假设=assumptions[]；声明=declaration；可用次数=remaining.revision；降级=drafts[].status；恢复标注=drafts[].is_selected / selected_stance。

## 4. 手机端（延续既有移动端规范，阶段 2.4）

- 单断点 `@media (max-width: 480px)`，单列堆叠——三卡本就垂直排在单列详情面板内，无需额外布局切换；桌面亦为单列（`#item-detail` 现状），手机端仅放大触控目标。
- 触控目标：卡内所有按钮/chip 在 480 内提至 44px（沿用 `--btn-height` 与既有 480 内提升规则）。
- 版本块（方案一/二/三）在手机端保持垂直堆叠，不做横滑、不做折叠以外的花式——零动画红线延续。
- 刷新恢复后滚动位置由既有 `history.scrollRestoration="manual"` 机制接管，三卡不加自己的滚动逻辑。
- 明确不做：转场动画、缩字号、新断点、横滑容器。

## 6. 交互流（完整点击路径）

```
① 点开「需关注」检查项详情
   → GET  /api/review/{rid}/items/{iid}/revision/state   （纯读库，恢复三卡）
② 点「生成修改建议」（卡一，用户显式点按）
   → POST /api/review/{rid}/items/{iid}/revision         → 三版草案 + 理由 + 假设 + 声明
③ 点某版本块内「选定这一版」
   → POST /api/review/{rid}/items/{iid}/revision/select  → 卡二更新「已选定：X 版」
④ 点「检查其他条款」（卡三）
   → POST /api/review/{rid}/items/{iid}/revision/impact  → findings / uncovered / degraded
⑤ 刷新页面（任意时点）
   → 只调 ① 的 GET state；只读渲染；绝不自动触发 ②③④
⑥ 导出报告（B7-3b，本线框外）
   → GET  /api/review/{rid}/report；页面预留 W19 提示位（卡二正常态尾部一行 caption）
```

失败路径纪律：②③④ 任一失败只展示对应降级文案；「再试一次」必须用户显式点按；次数用尽时按钮置灰 + 说明文案，前端绝不自行重试或换路重发。

## 7. B7-3b 预留说明

导出报告将包含您选定的方案——入口提示位（W19）固定放在卡二正常态尾部一行弱说明（`--color-text-tertiary`），B7-3b 合并前该行可先不渲染；章节本体不在本线框范围。
