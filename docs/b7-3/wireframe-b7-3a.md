## 1.5 页面读取失败层（GET state 自身失败——与 AI 生成失败严格分开）

读取失败时三卡整体不渲染，原位置显示一条占位状态行（同一虚线容器、`--color-text-secondary` 灰、无红色告警）。读取失败的重试按钮文案固定为「重新读取」，语义=只重发 GET state（纯读库），**绝不触发任何 AI 调用**；卡内的「再试一次」（AI 生成失败专用）是另一个按钮、另一种语义，两者不得复用文案与样式。

```
┌──────────────────────────────────────────────┐
│ 〔读态A 网络断开 / 请求超时〕                   │
│   暂时读不到您的方案记录，请检查网络后重新读取。 │
│   ( 重新读取 )   ← 仅重发 GET state；失败可反复点，零消耗 │
│                                              │
│ 〔读态B 登录过期（401）〕                       │
│   登录已过期，请重新登录后再查看。               │
│   ( 重新登录 )   ← 跳转登录；登录后回到本检查项详情， │
│                    返回时自动重发一次 GET state（仍是纯读） │
│                                              │
│ 〔读态C 审查单过期或不存在（404）〕              │
│   这份审查记录已过期或不存在，无法查看修改建议。  │
│   ( 返回清单 )   ← 无「重新读取」按钮（重读必然再 404） │
└──────────────────────────────────────────────┘
```

判定与纪律：按 HTTP 状态分态（超时/网络错误→读态A，401→读态B，404→读态C，其余 5xx 归入读态A）；「重新读取」路径上只有 GET，代码评审按此验收；读取失败态下三卡按钮一律不出现，防止用户在未知状态下误触 AI 调用。

新增文案位（并入 §5 清单）：
| W20 | 读取层·网络 | 暂时读不到您的方案记录，请检查网络后重新读取 | GET 失败 |
| W21 | 读取层·登录 | 登录已过期，请重新登录后再查看 | 401 |
| W22 | 读取层·不存在 | 这份审查记录已过期或不存在，无法查看修改建议 | 404 |
| W23 | 读取层按钮 | 重新读取（只重读记录，不产生任何消耗） | — |

**字段来源待后端确认（如实标记，不发明字段）**：现有 §四A 样例中 impact 只有单值 `state:"uncovered"`，未区分 F1（检索过、词族未命中）与 F2（合同全文缺失无法检索）。线框按两态出文案与渲染位；落地前与后端对齐：聚合接口 state 返回补 `uncovered_reason:"no_match"|"missing_source"` 机器可读字段（后端 impact 报告 payload 已有对应文本依据，接口微调走既有送审流程）。**对齐结论出来前，两态不得合并渲染**。

## 4. 手机端（延续既有移动端规范，阶段 2.4）

## 6. 交互流（完整点击路径）

```
① 点开「需关注」检查项详情
   → GET  /api/review/{rid}/items/{iid}/revision/state   （纯读库，恢复三卡）
② 点「生成修改建议」（卡一，用户显式点按）
   → POST /api/review/{rid}/items/{iid}/revision         → 三版草案 + 理由 + 假设 + 声明
③ 点某版本块内「选定这一版」
   → POST /api/review/{rid}/items/{iid}/revision/select  → 卡二更新「已选定：X 版」
④ 点「检查其他条款」（卡三）
   → POST /api/review/{rid}/items/{iid}/revision/impact  → findings / uncovered / degraded
⑤ 刷新页面（任意时点）
   → 只调 ① 的 GET state；只读渲染；绝不自动触发 ②③④
⑥ 导出报告（B7-3b，本线框外）
   → GET  /api/review/{rid}/report；页面预留 W19 提示位（卡二正常态尾部一行 caption）
```

失败路径纪律：②③④ 任一失败只展示对应降级文案；「再试一次」必须用户显式点按；次数用尽时按钮置灰 + 说明文案，前端绝不自行重试或换路重发。

## 6.5 竞态与防重

- **过期响应不覆盖**：每个在途请求记录发起时的（检查项 id + 批次 draft_id）上下文；响应返回时与当前页面上下文比对，不一致即丢弃——用户切换条款或批次后，前一个迟到返回不得改动当前显示。GET state 同理（切项后旧项的 state 响应不渲染）。
- **在途置灰**：②③④ 任一请求进行中，对应按钮置灰并显示「正在生成…」/「正在检查…」，同一位置同一时刻只允许一个在途请求；选定请求同样置灰防双击，但无消耗提示（选定免费）。
- **重试消耗明示**：卡一/卡三的「再试一次」旁固定一行 caption：「再试一次将消耗一次可用次数（剩 N 次）」——重试也是一次真实 AI 调用；remaining 为 0 时重试按钮不出现，只保留已达上限文案。
- **读取重试例外**：§1.5「重新读取」是纯读操作，不消耗次数，按钮旁不加上述消耗提示（这正是它与 AI 重试按钮的语义分界）。
