## 〇、验收边界声明（按老板 2026-11-03 核对口径）

联合验收（docs/m7/acceptance-b73-filled.md）的性质是：**把 I1/I2 两份
考卷的留痕重新组装到一份样例报告里，对报告章节做离线抽查核对**；回放
时原文引句剥离了省略号（验收单已记录）。它支持这两组样例的离线报告
核对，**不等同于线上完整操作链验收**（生成→选定→牵连→刷新恢复→导出
的线上全链验证在换装后验收关进行，见 §五），也不宜笼统称为全部内容
逐字无改动。本部署单 §五 的线上验收关即补这一环。

## 四、回滚预案（同卷回退，兼容性已验证）

- 沿用 B7-2 §四 法 B：回退镜像 `agent-t:571d179` + **同一宿主卷**
  （法 A 直接复活旧容器会丢新写入，已由演练排除）
- **新表向后兼容旧代码（已核 571d179 源码）**：旧 DDL 为
  CREATE TABLE IF NOT EXISTS（表已存在不覆盖）；旧 INSERT 显式列名

## 五、换装后验收关（新增线上全链环）

离线抽查（#167）不能替代线上全链——换装后按序跑通以下**一条龙**，
任一步不过即触发 §四回滚并中止上线宣告：

1. 只读探针：/health 200、`server_revision`=冻结 SHA、库探针
   （reviews 行数基线、impact_reports 行数、stance 列存在性
   PRAGMA table_info）
2. 上传验收卷（fixtures/m7/i1-impact-linked.txt，采购品类）→ 审查完成
3. **线上全链**：页面三卡生成（消耗 revision 1 次）→ 选定平衡版 →
   牵连检查（消耗 impact 1 次）→ 刷新页面三卡状态恢复（GET state
   零扣额：账本无新增行）→ 导出报告含第四节且与页面选定一致 →
   失效路径：将记录过期后访问 state 返回 404
4. **费用口径（v2：逐节点重算整条链，codex #168 复批 P1 修正）**

   验收一条龙从**上传**开始：上传触发既有审查主链（预审/品类建议/
   模型评审/质量层），不是只有 revision+impact 两次调用。逐节点上界
   （阀门=代码登记常量；牌价=Flash 峰值输出 ¥8/M；估算非实付）：

   | 节点 | 触发条件（换装执行时**重探 env**，下表按 B7-2 生产实探） | 次数×输出阀门 | 上界输出 |
   |---|---|---|---|
   | precheck | 代码默认=true（生产未设 env） | 1×3000 | 3k |
   | category_suggest | CATEGORY_SUGGEST_ENABLED=开（B7-2 实探在） | 1×16000 | 16k |
   | model_review | DEEPSEEK_API_KEY 在位 | ≤6×13000 | 78k |
   | quality | QUALITY_ENABLED 默认开 | ≤6×25000 | 150k |
   | revision（本单验收） | 三卡生成 1 次 | 1×16000 | 16k |
   | impact（本单验收） | 牵连检查 1 次 | 1×8000 | 8k |
   | **合计上界** | | **271k → 峰值 ≈ ¥2.17**（输入另计 <¥0.1） | |

   **实付口径**：¥2.17+ 为峰值估算，非现金实付、不构成不超限的保证；
   M6.5 历史锚点（峰值估算 ¥5.62 vs 余额差实扣 ¥2.68）表明实际通常
   远低于阀门上界。

   **预算两案（上界 ¥2.17+输入 已超现控值 ¥2，须老板先定案再跑，
   沉默≠审批不设默认）**：
   - **方案 A（开发团队推荐）**：验收预算控制值调至 **¥3/次业务流**
     （按例预留覆盖 271k 上界+输入余量）；质量层真实链路在验收中
     被覆盖
   - **方案 B**：验收上传时显式 `QUALITY_ENABLED=false` 缩范围
     （上界降至 121k ≈ ¥0.97+输入，¥2 控值够用）；代价=验收不含
     质量层真实链路，且改生产开关本身是一项变更

   **可预留 vs 只能事后对账（如实限定）**：
   - **请求前可预留**：整链输出上界由代码登记阀门决定，开跑前可
     复算——按例预留校验「**账本累计 + 本例全链上界 < 控制值**」才
     开跑（含 revision/impact 两次一并预留）；revision/impact 另受
     线上交互闸（每卷 4/3 次）约束，本单验收各只跑 1 次
   - **只能事后对账**：主审查链四节点（precheck/category_suggest/
     model_review/quality）是既有生产代码，**无逐节点熔断**（B7-2 v6
     结论沿用：插熔断=超范围变更另行立项）——控制机制=单样本独立
     review_id + 跑完即按该单号严格圈账（STRICT_SPENT_CODE；缺行/
     缺用量/查询失败=费用未知）
   - **停止规则**：费用未知 / 实算 ≥ 控制值（A=¥3、B=¥2，老板定案）
     → **不再跑任何后续验收项**并报备；失败不重试不追跑
   - 跑前 DeepSeek 余额探针照旧（余额 < 控制值即拒跑）
5. 验收产物：执行日志（含全 SHA、行数基线、账本峰值、截图/账本导出）
   入档 docs/m7/deploy-execution-b73.md，PR 送审
