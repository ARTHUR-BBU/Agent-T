## 〇、验收边界声明（按老板 2026-11-03 核对口径）

联合验收（docs/m7/acceptance-b73-filled.md）的性质是：**把 I1/I2 两份
考卷的留痕重新组装到一份样例报告里，对报告章节做离线抽查核对**；回放
时原文引句剥离了省略号（验收单已记录）。它支持这两组样例的离线报告
核对，**不等同于线上完整操作链验收**（生成→选定→牵连→刷新恢复→导出
的线上全链验证在换装后验收关进行，见 §五），也不宜笼统称为全部内容
逐字无改动。本部署单 §五 的线上验收关即补这一环。

## 五、换装后验收关（新增线上全链环）

离线抽查（#167）不能替代线上全链——换装后按序跑通以下**一条龙**，
任一步不过即触发 §四回滚并中止上线宣告：

1. 只读探针：/health 200、`server_revision`=冻结 SHA、库探针
   （reviews 行数基线、impact_reports 行数、stance 列存在性
   PRAGMA table_info）
2. 上传验收卷（fixtures/m7/i1-impact-linked.txt，采购品类）→ 审查完成
3. **线上全链**：页面三卡生成（消耗 revision 1 次）→ 选定平衡版 →
   牵连检查（消耗 impact 1 次）→ 刷新页面三卡状态恢复（GET state
   零扣额：账本无新增行）→ 导出报告含第四节且与页面选定一致 →
   失效路径：将记录过期后访问 state 返回 404
4. **费用口径（v3：含重试与供应商差异+圈账改 trace 主键，codex #168
   二轮 P1×2 修正）**

   **验收执行配置（先钉死，费用按此算）**：验收卷上传**带 force=1
   直通**（用户已在验收侧拍板品类，跳过品类确认弹窗分支）。已核代码：
   force 跳过 category_suggest（routes.py `not force` 条件）→ 品类建议
   节点=0 次，且不存在「确认提前返回、review 未建」的无单号分支。

   逐节点上界（阀门=代码登记常量，**含重试**；牌价=Flash 峰值输出
   ¥8/M 统算——品类建议实走 Cloudflare clef-flash（最便宜档，P1-1
   用户拍板），按 Flash 峰值统算=保守口径；估算非实付）：

   | 节点 | 供应商 | 重试上界（已核代码） | 次数×阀门 | 上界输出 |
   |---|---|---|---|---|
   | precheck | DeepSeek | **≤2 次**（首查解析失败重试 1 次，precheck.py attempt 循环，逐次预算闸） | 2×3000 | 6k |
   | category_suggest | Cloudflare clef-flash | **0 次**（force=1 直通跳过；带重试的非 force 路径见附注） | 0 | 0 |
   | model_review | DeepSeek | ≤6 条评审 | 6×13000 | 78k |
   | quality | DeepSeek | ≤6 维观察 | 6×25000 | 150k |
   | revision | DeepSeek | 1 次（线上交互闸内） | 1×16000 | 16k |
   | impact | DeepSeek | 1 次（线上交互闸内） | 1×8000 | 8k |
   | **合计上界** | | | **258k → 峰值 ≈ ¥2.06**（输入另计 <¥0.1） | |

   附注（非验收路径，如实记录）：若不带 force，品类建议 ≤2×16000
   （瞬态网络异常重试 1 次，category_suggest.py 瞬态白名单+二次扣减）
   另加 ≤32k；确认弹窗分支若发生会重传再跑一轮 precheck。验收选
   force=1 即为避开这两处无单号/双份路径——这是**执行配置决策**，
   不是漏算。

   **实付口径**：¥2.06+ 为峰值估算，非现金实付；M6.5 锚点（峰值估算
   ¥5.62 vs 余额差实扣 ¥2.68）表明实际通常远低于上界。

   **预算两案（上界 ¥2.06+输入 贴着现控值 ¥2，仍须老板先定案，
   沉默≠审批）**：
   - **方案 A（开发团队推荐）**：控制值调 **¥3/次业务流**（覆盖 258k
     上界+输入余量）；质量层真实链路被覆盖
   - **方案 B**：验收上传显式 `QUALITY_ENABLED=false`（上界 108k
     ≈ ¥0.86+输入，¥2 控值够用）；代价=验收不含质量层真实链路，
     且改生产开关本身是变更

   **圈账方案（v5：用量收严+归属可证明+独立证据区间，codex 四轮
   P1×2 修正）**：

   - **全链不是同一个 trace（已核代码）**：上传/主链走上传 trace
     （reviews.data.trace_id）；**revision / impact 各自生成新
     trace**（revision_drafts.trace_id / impact_reports.trace_id）。
     **执行协议**：executor 每步操作后如实记录三枚 trace + review_id；
     无单号时若能从服务端日志拿到上传 trace，按 trace 归属（可证明）
   - **归属必须可证明（四轮 P1-2）**：取行口径只有两条——
     `review_id=rid` 或 `trace_id ∈ 三枚记录`。**水位增量扫描只做
     诊断、绝不计入对账**：并发下其他用户的账行无法证明归属，出现
     即出诊断提示（人工核对 call_id），宁可费用未知=停
   - **用量校验收严（四轮 P1-1）**：usage 必须为对象且
     output_tokens/input_tokens **两键齐备、非负有限数值**——
     空对象/null/缺单键/非数值/负数/inf/nan 一律「费用未知」，
     绝不用 `or 0` 把未知转零元；非合法行不计费但仍标 unknown
   - **局限承认（五轮，实锤演示在案）**：**现状单账（只有账本）无法
     当场证明逐笔完整**——transport 单点（llm_client）除账本外无
     第二份逐笔记录（已核代码）；区间预期 [1,2] 下「实际 2 笔、
     第二笔账行丢失」返回 ok。模拟流水演示
     `tools/m7/simulate_b73_chain.py` 场景 1 如实复现该盲区（零付费）。
     质量层为短合同**合并调用**（1 次覆盖多维度）+解析失败可重试——
     调用次数 ≠ 维度数，条目/维度数不能当预期次数。
   - **两案呈批（由老板决定接受局限或批准小变更；沉默≠审批）**：
     - **方案一（开发团队推荐）**：`llm_call_log.emit` 加一行
       transport 审计日志（call_id/trace/node/outcome，**5 行级
       fail-safe 变更**，不动账本语义、不影响主链）——账本与审计
       日志**同点写、互为对方缺账的证据**，双账逐笔当场核对可证明。
       核对器已实现双账模式（`audit_lines` 参数）并有正反验证：
       模拟流水删第二次 precheck 账行 → 当场 unknown（演示场景 2）；
       质量层合并调用按审计行数当次数不误报（演示场景 3）；
       `tests/test_reconcile_b73.py` 双账 4 场景 + 既有场景全绿
     - **方案二**：接受局限声明——验收控制降级为「阀门上界预留 +
       事后供应商账单对账（异步第二本账）+ 本局限书面接受」；
       接受后 precheck 区间口径保留但如实标注「第二笔缺失无法当场
       发现」
   - **预期清单=独立证据（不拿账本定预期）**：
     - suggest=0（force 请求参数）
     - revision=1、impact=1（executor 主动触发拿到 200）
     - model_review / quality：**调用次数≠条目/维度数**（质量层短
       合同合并调用+可重试）——以方案一双账审计行数为准；方案二下
       如实声明无独立次数证据
     - precheck ∈ [1,2] 区间（上传响应 performed 证明 ≥1；第 2 笔
       外部无独立证据——见局限承认）
     - 低于区间/审计行数下界=缺账（费用未知）；高于上界=多行
       （费用未知）；区间内按已见行 usage 计费
   - **可执行核对器+零付费正反验证**：
     `tools/m7/reconcile_b73_acceptance.py`（纯本地 SQLite 只读）+
     `tests/test_reconcile_b73.py` **24 场景**（用量 {} / null / 缺
     单键 / null 值 / 负数 / 字符串 / inf 全反例；并发他人行不计入
     +诊断提示；无单号有 trace=ok、无 trace=unknown；区间三态；
     双账缺行/节点不符/覆盖区间预期）全绿
   - **停止规则**：费用未知 / 实算 ≥ 控制值（A=¥3、B=¥2，老板定案）
     → **不再跑任何后续验收项**并报备；失败不重试不追跑
   - 跑前 DeepSeek 余额探针照旧（余额 < 控制值即拒跑）
5. 验收产物：执行日志（含全 SHA、行数基线、账本峰值、截图/账本导出）
