## 〇、验收边界声明（按老板 2026-11-03 核对口径）

联合验收（docs/m7/acceptance-b73-filled.md）的性质是：**把 I1/I2 两份
考卷的留痕重新组装到一份样例报告里，对报告章节做离线抽查核对**；回放
时原文引句剥离了省略号（验收单已记录）。它支持这两组样例的离线报告
核对，**不等同于线上完整操作链验收**（生成→选定→牵连→刷新恢复→导出
的线上全链验证在换装后验收关进行，见 §五），也不宜笼统称为全部内容
逐字无改动。本部署单 §五 的线上验收关即补这一环。

## 五、换装后验收关（新增线上全链环）

离线抽查（#167）不能替代线上全链——换装后按序跑通以下**一条龙**，
任一步不过即触发 §四回滚并中止上线宣告：

1. 只读探针：/health 200、`server_revision`=冻结 SHA、库探针
   （reviews 行数基线、impact_reports 行数、stance 列存在性
   PRAGMA table_info）
2. 上传验收卷（fixtures/m7/i1-impact-linked.txt，采购品类）→ 审查完成
3. **线上全链**：页面三卡生成（消耗 revision 1 次）→ 选定平衡版 →
   牵连检查（消耗 impact 1 次）→ 刷新页面三卡状态恢复（GET state
   零扣额：账本无新增行）→ 导出报告含第四节且与页面选定一致 →
   失效路径：将记录过期后访问 state 返回 404
4. **费用口径（v3：含重试与供应商差异+圈账改 trace 主键，codex #168
   二轮 P1×2 修正）**

   **验收执行配置（先钉死，费用按此算）**：验收卷上传**带 force=1
   直通**（用户已在验收侧拍板品类，跳过品类确认弹窗分支）。已核代码：
   force 跳过 category_suggest（routes.py `not force` 条件）→ 品类建议
   节点=0 次，且不存在「确认提前返回、review 未建」的无单号分支。

   逐节点上界（阀门=代码登记常量，**含重试**；牌价=Flash 峰值输出
   ¥8/M 统算——品类建议实走 Cloudflare clef-flash（最便宜档，P1-1
   用户拍板），按 Flash 峰值统算=保守口径；估算非实付）：

   | 节点 | 供应商 | 重试上界（已核代码） | 次数×阀门 | 上界输出 |
   |---|---|---|---|---|
   | precheck | DeepSeek | **≤2 次**（首查解析失败重试 1 次，precheck.py attempt 循环，逐次预算闸） | 2×3000 | 6k |
   | category_suggest | Cloudflare clef-flash | **0 次**（force=1 直通跳过；带重试的非 force 路径见附注） | 0 | 0 |
   | model_review | DeepSeek | ≤6 条评审 | 6×13000 | 78k |
   | quality | DeepSeek | ≤6 维观察 | 6×25000 | 150k |
   | revision | DeepSeek | 1 次（线上交互闸内） | 1×16000 | 16k |
   | impact | DeepSeek | 1 次（线上交互闸内） | 1×8000 | 8k |
   | **合计上界** | | | **258k → 峰值 ≈ ¥2.06**（输入另计 <¥0.1） | |

   附注（非验收路径，如实记录）：若不带 force，品类建议 ≤2×16000
   （瞬态网络异常重试 1 次，category_suggest.py 瞬态白名单+二次扣减）
   另加 ≤32k；确认弹窗分支若发生会重传再跑一轮 precheck。验收选
   force=1 即为避开这两处无单号/双份路径——这是**执行配置决策**，
   不是漏算。

   **实付口径**：¥2.06+ 为峰值估算，非现金实付；M6.5 锚点（峰值估算
   ¥5.62 vs 余额差实扣 ¥2.68）表明实际通常远低于上界。

   **预算两案（上界 ¥2.06+输入 贴着现控值 ¥2，仍须老板先定案，
   沉默≠审批）**：
   - **方案 A（开发团队推荐）**：控制值调 **¥3/次业务流**（覆盖 258k
     上界+输入余量）；质量层真实链路被覆盖
   - **方案 B**：验收上传显式 `QUALITY_ENABLED=false`（上界 108k
     ≈ ¥0.86+输入，¥2 控值够用）；代价=验收不含质量层真实链路，
     且改生产开关本身是变更

   **圈账方案（v3：trace 主键+预期清单逐笔核，codex 二轮 P1-2）**：

   - trace_id 单点生成于上传入口（routes.py，已核）——上传阶段
     precheck 行以 trace 落账（建单前 review_id 为空，建单成功后
     `backfill_review_id(rid, trace_id)` 幂等回填，routes.py 已核）
   - **验收路径无 confirm 提前返回**（force=1）→ 单请求单 trace，
     建单必成 → 全链账行同挂 (review_id, trace_id)
   - **逐笔核账 ≠ 只查 STRICT_SPENT_CODE**（如实限定：它只发现已
     存在行的缺 usage，不证明应有行存在）——核对脚本按 trace_id 取
     全部账行，与**预期调用清单**（上表 6 节点的 node×次数集合）
     逐笔比对：缺行/多行/任一行缺 usage/查询失败 = **费用未知 = 停**
   - **停止规则**：费用未知 / 实算 ≥ 控制值（A=¥3、B=¥2，老板定案）
     → **不再跑任何后续验收项**并报备；失败不重试不追跑
   - 跑前 DeepSeek 余额探针照旧（余额 < 控制值即拒跑）
5. 验收产物：执行日志（含全 SHA、行数基线、账本峰值、截图/账本导出）
   入档 docs/m7/deploy-execution-b73.md，PR 送审
