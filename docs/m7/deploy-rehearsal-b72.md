## 逐阶段记录

### 阶段 1：构造 WAL 形态

临时容器（appuser）建库写 7 行后 `os._exit(0)` 跳过解释器关闭
（无 checkpoint），文件集：`src.db` 4096B + `src.db-wal` 20632B +
`src.db-shm`——与生产「已提交事务滞留 WAL」同构。

**过程中踩到并验证了部署单的权限课**：docker 自动建挂载目录归 root，
appuser 写入即 `unable to open database file`——`chown 1000:1000` 前置
的要求是必要的（已写入部署单 §2.2/§2.3）。

### 阶段 2a：陷阱复现（只拷主库）

`cp src.db mig.db`（无 WAL）→ 打开后 **`no such table: reviews`**：
建表 DDL 与 7 行数据全部滞留 WAL，主库接近空壳。证明「停机后只拷主
文件」在 WAL 形态下丢失全部未检查点事务。

### 阶段 2b/2c：正确迁移

三件套（db+wal+shm）`chown 1000:1000` 后，backup API 收敛单文件 →
`PRAGMA integrity_check` ok → **源/快照 reviews 7/7 一致（脚本 assert
fail-closed，非人工看输出）**。

### 阶段 3：迁移后新写入的回退对照

- 新容器语义侧写入 `NEW_WRITE` 行并提交
- **法 A（v6 原文：直接复活旧容器）**：旧容器无挂载、读自身 /tmp 旧库
  → NEW_WRITE **丢失**（演练中旧库样本连 reviews 表都缺）——证实
  codex 判断：rename 回原名直接 start 不能保新写入
- **法 B（v7 采纳：新卷库拷回旧容器再启动）**：`cp 新卷库 → 旧容器
  /tmp/agent-t-reviews.db`（docker cp 进旧容器 + chown 1000）→
  NEW_WRITE **保住**（=1）

**回退语义定稿（写入部署单 v7）**：
- 尚无新写入阶段（停机-迁移中失败）：直接复活旧容器即可（原件未动）
- 已有新写入阶段（新容器已上线后回滚）：**必须把宿主卷当前库拷回旧
  容器内路径再启动**——或等价地继续用旧镜像+同一新卷+STORE_DB_PATH
  （#148 已支持）重启

## 演练即证据：部署单 v7 相应修正点

1. §2.3.8① 补齐 WAL/SHM 实际拷贝命令（按在线记录的存在性，失败即中止）
2. §2.3.8 对比脚本升级为 assert fail-closed（v6 已有，演练验证其有效性）
3. 回退分支 ③ 改为法 B 语义，并标注法 A 仅限尚无新写入阶段
4. §2.3.4 隔离入口加「外部实测」：iptables 规则加后从本地
   `curl http://<IP>:8080/health` 必须失败（超时/拒绝）、删规则后恢复
   200——规则命中实际流量才算隔离成立；本机运维 ssh 通道不受影响
