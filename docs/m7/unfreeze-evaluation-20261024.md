## 四、待裁定决策点（呈老板+外审；codex 复核建议已吸收，仍待正式裁定）

1. **修改建议是否进 docx 报告**——⚠️ 这是**范围决定，不是导出格式调整**：现行路线图「明确不做」明确列入「报告 docx 不引入 LLM 生成内容」。若 M7 纳入导出，**前置=先正式修订该范围条款**（修订本身走流程），再谈导出形态。建议方向：docx 设**明确标识的「修改草案」章节**（与正文判定区隔、标注为 AI 起草辅助），确定性来源=固定模板+已落库草案文本，不新增 LLM 调用。未修订禁令前，按「只在 Web 展示层」施工。
2. **A/B/C 生成形态**：**建议三版一次生成**（单次调用+结构化输出+Schema 校验；省费；阀门按单次上限登记）——评估与 codex 复核建议一致；开工前出费用上限单（复用 #138 机制，实测生产账本定数字）。验收补一句：**三版或必填字段不完整 → 整项降级，不展示残缺方案**（宁缺毋残，残缺建议比没有更危险）。
3. **4.2 连带影响扫描范围**：**建议先查相关条款簇，查不到即如实标「未覆盖」**（stage1 索引已支持；不承诺全卷扫描，未覆盖不装覆盖）。附带设计约束：连带影响提示只做**定位与不一致报告**，不验证草案生效——「采纳后是否解决问题」须以重新审查验证。
4. **采纳操作流**：**建议「用户选定草案」单独留痕**（新增最小记录，不复用既有 adopt 接口——那是规则改进提案通道，语义不同）；该记录是 4.2 触发前提+可追溯依据。
