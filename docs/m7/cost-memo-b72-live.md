## 二、执行保护（沿用 v3 全套，逐项写明）

1. **跑前预检**：DeepSeek 余额查询，余额 < ¥2.00 即拒跑。
2. **版本比对**：caller HEAD 与服务端镜像标签必须一致；**实跑前置=部署含
   #154 的版本并完成版本比对**（部署按 SOP 单独请示，不在本单授权内）。
   **部署单核对项（老板 2026-10-29 指示）**：B7-1 实跑时部署过含 #148 的
   版本（当时镜像 95555ed），生产当前具体版本以部署前的实际核查为准——
   部署单必须先核生产在跑版本，再走换容器流程。
3. **逐样本圈账+逐请求预算边界**：每样本完成按本批真实单号精确圈账并
   打印累计；**发下一请求前**校验「累计+下一请求最坏 < ¥2.00」，不满足
   拦截不发（可执行边界，见 §一硬上限行）；累计已知超限同样立即停止。
4. **停止条件全列**：①累计费用 ≥ 硬上限；②任何样本非预期异常（拒绝类
   样本的「拒绝」本身是预期结果）；③连续 2 样本失败（transport 失败与
   基础设施失败**合并同一本计数册**，成功清零——#149 整改口径）。
   停止后已产生费用如实结算入报告，不重试不追跑。
5. **精确圈账口径**：按本批 5 个 review_id（SQL WHERE review_id IN），
   别家消费不入账；账本行按节点分列核对（revision/impact 各查各的）。
6. **阅卷判据（新增，防假绿）**：I1 摘录混入被改条款原文→判不通过；I2
   未覆盖措辞缺「不代表没有冲突」→判不通过；金标要求 N 次调用而账本
   0 行（或反之）→判不通过；选定版草案超 2000 字上界→拒判（费用上界
   完整性）。
7. **种单清理**：跑后清理覆盖 reviews/revision_drafts/revision_budget/
   selected_drafts/impact_reports 五表（逐表容错）；llm_calls 账本保留供审计。
