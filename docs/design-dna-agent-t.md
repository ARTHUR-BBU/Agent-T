# Agent-T 设计 DNA：清晰的合同审查工作台

## 设计主张
像一份整理有序的案卷：沉静、可信、精确，让人把注意力放在合同、证据与判断上。界面以中文阅读和连续审查为中心，不用装饰与高饱和色抢走结论。

## 页面层级
1. 顶栏负责识别产品，左栏负责切换合同和入口；主要行动使用同一种深绿色。
2. 审查结果先交代合同和阅读范围，再进入「审查清单」和「条目详情」；两个工作区标题、间距及分隔线遵循同一规则。
3. 清单以整行选中态和文字状态标识当前对象；右侧汇集选中条目的说明、原文、建议与讨论。风险、引用和人工确认不得因为美化而隐藏。
4. 页面和面板底部保留足够空白；长文本能换行，各栏维持各自滚动和可拖动宽度。

## 字体与排版
- 不依赖外部字体服务：优先系统中文字体（PingFang SC、Microsoft YaHei、Noto Sans SC）。中文正文 15px、1.65 倍行高；说明文字一般不小于 13px；标题 27px、工作区标题 17px。低优先的英文辅助标记仅作装饰，不能替代中文标题。
- 用字重、间距、轻分割区分层次；相邻区块优先用留白，不给所有内容套重边框。字号随窄屏调整，长合同文本按原文换行。

## 色彩和语义
- 画布暖灰 `#f3f3ef`、纸面白 `#ffffff`、正文深墨绿 `#1e302e`、辅助文字 `#52645f`、分隔 `#dce4df`。
- 深绿 `#176b5d` 用于主要操作、焦点和选中；不能代替通过/需关注等规则结论。
- 状态颜色服务于语义：通过为温和绿色、需关注为琥珀色、未找到与不适用为中性灰；永远同时显示文字，不只靠颜色。
- 保持可见焦点、文本与背景的足够对比；需要人工确认和风险提示不因视觉统一被降级。

## 组件与行为
- 导航和主要按钮统一圆角及密度；边框和轻阴影仅用于区分可交互区域与内容层。
- 事实材料、列表、详情、提案和对话共享相同的颜色、字号和间距语言，但按用途区分表面与标题。
- 桌面三栏可拖动、键盘可调，列宽受限；窄屏回退原有单栏/抽屉，立场、导出说明和底部内容不得被截断。
- 优先即时、克制的交互反馈，尊重减少动态效果；合同摘句和用户输入作为文本展示。

## 变更约束
视觉改动不得改变审查档位、人工确认权限、规则发布语义或文档内容；新组件须复用此文档的层级和色彩，并覆盖桌面、窄屏、键盘及长文本。

## 导航选中状态补充（2026-11-08）
- 根据用户偏好，左侧栏导航文字与“本份合同”标题统一为 12px；悬停、键盘焦点和当前项分别使用可辨别的反馈，当前项同时提供语义标记。导航不可用时明确禁用，不制造虚假的选中状态。
- 清单选中与对应侧栏项同步；没有对应侧栏条目时回到“清单”。合同切换加载时隐藏旧导航；结果重绘关闭详情时不能继续高亮旧条目。修改方案与对话范围也使用文字/语义及视觉状态共同标记。

## AI 发现与条目正文补充（2026-11-08）
- AI 发现各条目保持左右内边距、适当行距和清晰边界；原文引用、主要确认、次要异议及讨论操作在颜色、边框和文字上有明确区分，并保留键盘焦点和禁用状态。
- 条目详情及对应对话工作台的正文统一为 13px，包含说明、原文、示范条款、方案和对话内容；条目标题、分类和状态标签保留原有层级。该约定同时覆盖桌面及详情搬回清单的窄屏布局。
- 手机等窄屏的追问输入框保留 16px，以降低输入时浏览器自动放大页面的可能；这是输入控件的例外，正文仍为 13px。AI 发现中的手机操作按钮最小高度为 44px。
