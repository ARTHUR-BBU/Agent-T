## 老钱三裁摘要

1. **NDA：回填**。否认簇升 hardline（保密是主给付义务，否认=合同目的落空，入红线家族）；**例外条款豁免门**（公知/独立开发/第三方合法取得/例外列举——「不承担保密义务」在标准 NDA 例外条款有合法居所，最大误报雷区）；采购标签正则不照搬（NDA 无此栏目）；补 missing_as: 需关注（标题党防线，零翻转）
2. **租赁：不回填不新增**（14 项本无保密项——纠正事实基线；示范文本无保密栏目、加项制造常驻噪音）
3. **技术服务：day one 四态全带上**（5 份官方语料实证；**关键陷阱：制式引导句「保密义务如下：」含裸词，pass 须排除空引导形态**否则空白模板洗成通过——F-12 同款教训；missing_as 需关注定锤）——随 B2 落地

## T1 NDA YAML 增补（confidentiality_scope）

悬置簇（heuristic）+否认簇（hardline，民法典 501 条 note）+例外形态直捕+unless 豁免门+blank_flag（NDA 自有形态）。原有 pass all_of/not_found 不动。

## 施工发现两处（如实记账）

1. **配置层级错位**：老钱稿 blank_flag_pattern 放 rules 级，引擎消费在 pass 规则级（A2 实现口径）——已挪入 pass 规则；老钱稿后续引用注意
2. **留白档抬题（裁定内部张力）**：NDA missing_as=需关注 使「留白」从三品类基线的「未找到+旗标」抬为「**需关注+旗标**」（标题党防线与留白共用未找到出口）。取保守侧（不放过），施工卡明示；拆分需引擎未找到细分特性——**挂账：引擎 missing 细分（留白 vs 无信号），待有第二处需求再立项**
