## 二、四分类模型（用户补充①：先分类再定状态）

`_match_procurement_term` 返回的 hit_type 扩为五值（老钱签字前置条件：**unlabeled_numeric 链路原样保留**——「30日内完成交付」无标签合同不得从通过退回未找到）：

| hit_type | 语义 | 状态映射（YAML） |
|---|---|---|
| `anchored` | 白名单标签+实质内容（E1/E2/E3） | 通过（pass，require_hit_type） |
| `pending` | 标签+待定词（另行协商/待定等） | 需关注（need_attention，require_hit_type） |
| `blank` | 标签+空白占位/空标题 | 未找到+旗标（note 通道） |
| `unlabeled_numeric` | 无标签但数字+采购动作链+票头核对通过 | 通过（**存量行为原样保留**，汇总视同 anchored） |
| `none` | 标签无且数字链路无 | 未找到（维持 not_found 路径） |

逐**标签条款**（occurrence）分类后汇总（含 unlabeled_numeric 命中），优先级见 §五（老钱已签字）。MatchResult 增可选第六字段 `blank_flag: bool = False`（向后兼容：既有五字段断言不破坏），「有实质另有独立空白→通过+非阻断旗标」由它承载。

**老钱签字施工注释（三条，已纳入）：**
1. 同窗 E 优先已定，汇总层不得推翻——「委托期限3年，具体起止另行协商」判 anchored 不判 pending（时长已定仅起止悬置，防模板满篇黄灯）
2. blank 旗标 note 须附条款引句（quote），否则长合同找不到那处空白；文案中性
3. 「期限见附件」「按甲方通知」跨引用条款落 blank → 未找到+旗标，已知边界明示接受，本批不加正则

## 三、同分句绑定 + 实质锚定（用户补充②③）

**窗口**：标签命中点起，边界=。；，,;换行，上限 60 字符（mandate 日期区间在标签下一行——换行不断跨行取窗口，边界字符只终止段落级延续；实现：跨换行取至句号/分号，内含逗号换行均续，上限 60 字）。

**实质锚定（E1–E3，命中任一即 anchored）：**
- E1 数字时长：`[\d零〇一二两三四五六七八九十百]+(年|个月|天|日|个工作日|小时|周)`
- E2 真实数字日期：日期表达含至少一个阿拉伯数字（如 2026年、6月30日）
- E3 起止双锚：「自/从…(之日)?起」与「至/止」同现窗口，且**无占位证据**
- 正例守卫（不得误杀）：「合同履行期自生效之日起三年」「委托期限 自2024年1月1日至2024年12月31日止」「履行期限：自交付之日起6个月内完成交付」「自生效之日起至验收合格之日止」（事件止点无数字也算明确）

**占位证据（出现即 E1–E3 全部失效，除非另有无占位的 E1）：**
- `[＿_]\s*[年月日天时周]`（下划线紧邻时间单位）
- 连续空白（含全角空格）`[ 　]{2,}` 紧邻 `年|月|日|天`（**空格占位**——两份改账合同正是此形态；单空格不算，「在 3 日内支付」不受影响）
- 相邻反例：混合占位「＿＿年 或 2026＿年 5 月」、全角空格「　年　月　日」、正文单空格不误判

**待定词（X1，仅 E1–E3 全不中时判定）：**
`另行协商|另行约定|协商确定|待定|另行确定|届时(另行)?(约定|确定|商定)`

**分级：** X1 待定 → `pending`；有标签但无实质无待定 → `blank`。

## 四、YAML 三分支（本批只动采购 term 项）

```yaml
need_attention:
  - matcher: procurement_term
    require_hit_type: ["pending"]     # 待定期限→需关注
    note: 期限条款已填写但实质待定（另行协商等），届满点不确定，需关注
    class: heuristic
pass:
  - matcher: procurement_term
    require_hit_type: ["anchored", "unlabeled_numeric"]  # 实质期限+存量数字链路→通过
    note: 已约定明确的交付/履行期限
not_found: 维持现状
```

引擎配套：matcher 规则体支持 `require_hit_type`（缺省=任意 matched，向后兼容）；`_rule_matches`/`_match`/`_extract_hits_from_rule` 三处消费同一份匹配结果（不重扫）。blank 旗标：item 未找到分支对含 matcher 的 pass 规则补一次匹配器查询（regex 纯本地，开销微；注释说明非「四处复用」红线路径），hit_type=="blank" → note 换「检测到期限条款但时长留白（可能为未填写模板）」+条款引句，`blank_flag: true` 透传（schema 增列可选字段）。

## 五、冲突优先级（用户补充④，**待老钱签字**）

同一合同多条款并存时的汇总规则：

| 场景 | 判定 |
|---|---|
| 任一标签条款为 pending（待定） | **需关注**（最高优先） |
| 有 anchored；另有独立 blank 条款 | 通过 + 非阻断 blank_flag |
| 无 anchored，有 blank | 未找到 + blank_flag |
| 全无标签 | 未找到（维持） |

「同一履行事项 vs 独立事项」的工程近似：逐条款（分句级）独立分类，不做跨条款事项归并——待定条款自身已足以触发需关注；空白条款不拖累其他实质条款（避免「一处空白全盘未找到」的噪声）。
