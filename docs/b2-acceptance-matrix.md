# B2-1 验收单：13 项「通过/需关注/反例/证据形态」对照表

> 用途：对抗样例集验收蓝本（老钱 13 项设计稿工程化翻译）。每条 hardline/簇至少 2 条对抗（换措辞仍命中+反例不得命中）。
> 依据：老钱设计稿 2026-10-09+保密三裁 2026-10-10+B2 设计稿 v1.1.1。

## 1. subject（主体，existence）——照搬采购同构簇

| 档 | 样例 | 说明 |
|---|---|---|
| 需关注 | 「甲方：XX科技有限公司 乙方：XX工作室」（仅称谓无身份） | unless 补全信息组放行 |
| 通过 | 「法定代表人：张三 / 统一社会信用代码：91…」 | |
| 反例 | 主体项不新增词表，零新误伤面 | |

## 2. service_scope（服务内容与交付物，heuristic）

| 档 | 样例 | 说明 |
|---|---|---|
| 需关注 | 「服务内容按乙方标准执行」「视项目进展确定」 | 范围笼统词 |
| 需关注 | 「详见附件二」（System 1 提示：当前输入未见附件内容——**不改本项状态**，仅提示） | P2 实质锚定 |
| 通过 | 「功能模块：用户管理/订单管理…；交付物：源代码、部署文档」 | 功能词∧交付物词同分句 |
| 反例 | 「不交付源代码」→需关注（偏向委托方注记）；「交付源代码|源程序一并交付」→不据此需关注 | |
| 证据形态 | quote 引范围词所在分句 | |

## 3. acceptance（验收，hardline 双向）——本品类头号项

| 档 | 样例 | 说明 |
|---|---|---|
| hardline（偏向受托方） | 「验收标准以乙方交付为准」「乙方自行验收」 | 不得换措辞漏 |
| hardline（偏向委托方） | 「乙方须无条件通过验收」「免费重新开发直至甲方满意」「以甲方主观评价为准」 | 反向红线 |
| hardline（质量闭环豁免） | 「验收不合格的乙方仅负责修复，不承担任何违约责任」 | |
| 需关注 | 「系统上线运行即视为验收合格」（擅自使用视为认可，对委托方不利） | |
| 需关注（边界样本） | 「收到交付物后 10 日内未提出书面异议视为验收通过」——异议期合理**不标**；≤3 日标 | 民法典 620-622 检验期逻辑 |
| 通过（实质锚定） | 「验收标准：符合 GB/T… 国家标准」「按需求规格说明书第 3 节测试用例验收」 | 验收∧(功能/性能/技术指标/测试用例/国标/行标/规范) 同句 |
| 反例 | 「验收合格后付款」中的「验收」**不构成本项 pass 证据**（payment 语义域） | 跨项语义域纪律 |
| 证据形态 | quote 引验收标准句（含标准词） | |

## 4. schedule（期限，procurement_term 四分类移植）

| 档 | 样例 |
|---|---|
| 通过（anchored） | 「开发周期：自 2026 年 1 月 1 日至 2026 年 6 月 30 日止」 |
| 需关注（pending） | 「工期：另行协商」 |
| 未找到+旗标（blank） | 「交付日期：＿＿＿＿」 |
| 通过（unlabeled_numeric 存量） | 原样保留口径 |
| 技术特有需关注 | 「乙方有权单方顺延工期」「工期根据实际情况自行调整」 |

## 5. payment（价款，背靠背 hardline 照搬+note 限定）

| 档 | 样例 |
|---|---|
| hardline | 「以甲方从最终用户处收到全部款项作为付款前提」+措辞变化变体 ≥2 |
| 反例 | 「不采用背靠背结算模式」→unless 放行 |
| 需关注（技术特有） | 「验收合格后支付全部尾款」且全文无验收期限/标准；「初验/终验」终验标准悬空 |
| 通过 | 「分期支付」「里程碑付款」「预付款+进度款」 |
| note 限定（v1.1） | 法释〔2024〕11 号针对大型企业与中小企业间交易，非一切付款安排自动无效 |

## 6. breach（违约，F-2 移植+单向罚则）

| 档 | 样例 |
|---|---|
| F-2 豁免门 | 「任何一方对不可抗力造成的损失不承担违约责任」→放行；「乙方逾期…免除乙方全部违约责任」→拦 |
| 需关注（技术特有） | 「乙方逾期每日按千分之＿支付违约金」∧全文无甲方逾期付款责任词（对等性缺失） |
| 通过 | 「违约方应赔偿对方经济损失」 |
| 反例 | 「不免除其违约责任」（加责表述）不得命中 |

## 7. termination（解除与退出，existence；v1.1.1 中性说明）

| 档 | 样例 |
|---|---|
| 通过 | 「任何一方可提前 30 日书面通知解除本合同」 |
| 需关注（missing_as） | 全文无解除/终止约定 |
| 中性说明（v1.1.1） | B2-1 subtype=unknown，只提示「退出机制未约定」；民法典 857/858 语境待 subtype 就位（仅技术开发展示） |

## 8. ip（知识产权，existence+方向 hardline；v1.1 中性口径）

| 档 | 样例 |
|---|---|
| 需关注（missing_as） | 全文无归属约定（中性口径：未明确约定成果归属/既有成果边界/使用权转让权；**不用「沉默即失权」**） |
| hardline（偏向受托方） | 「一切成果知识产权归乙方所有」且无对价/背景知产例外 |
| hardline（偏向委托方） | 「开发形成的一切成果（含乙方既有成果）均归甲方」且无例外清单 |
| 需关注（heuristic） | 「双方共有」但无行使规则 |
| 通过（归属语义域） | 「技术成果知识产权归甲方所有」「背景知识产权仍归各方」——裸提及（「不得侵犯第三方知产」）不算 |
| 反例 | 「不得侵犯第三方知识产权」→不得据此通过（归属未约定） |

## 9. unfair_terms（双向 hardline）

| 档 | 样例 |
|---|---|
| hardline（偏向受托方） | 「按行业惯例执行」作唯一标准；「乙方不对开发成果的可用性/正确性作任何保证」；「甲方数据丢失乙方不承担责任」 |
| hardline（偏向委托方） | 「永久免费维护」「终身免费升级」「无限期质保」；「需求变更无条件纳入且不加价不顺延」 |
| 通过 | 「双方协商」「另行书面约定」 |
| 反例 | 「按行业惯例及国家标准执行」（有客观锚点）→不得命中（「按行业惯例」裸词要防连坐） |

## 10. confidentiality（四态 day one，老钱裁定三 YAML）

| 档 | 样例 |
|---|---|
| 需关注（悬置） | 「保密义务如下：另行协商」 |
| 需关注（否认） | 子项级「保密内容：无」；整栏「保密义务如下：无」；「无需保密」「不涉及保密」 |
| 通过（制式子项+实质） | 「保密内容（包括技术信息和经营信息）：双方因履行本合同知悉的技术资料…」（冒号同格） |
| 通过（跨格 tab） | 表格左格「保密内容」右格实质内容 |
| 通过（裸词排空引导） | 「应遵守的保密义务」——裸「保密义务」不被「保密义务如下：」空引导形态连坐（负向前瞻） |
| 留白+旗标 | 「保密内容（包括技术信息和经营信息）：」/「涉密人员范围：」冒号/tab 后空白（前瞻含 。；; 收尾） |
| 反例（本品类头号陷阱） | 制式空模板「…保密义务如下：」→**不得通过**（字段名不创设义务）；缺失判 missing_as 需关注 |
| 证据形态 | quote 引子项标签+实质内容 |
