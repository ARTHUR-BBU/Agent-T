# 账户与规则管理威胁模型

日期：2026-11-09。当前系统为单工作区、可选共享 Basic Auth；账户功能开发期间维持默认关闭和本机隔离。新账户基础尚未使合同数据自动隔离，不得标为多人生产可用。

## 保护对象与信任边界

保护个人凭据、会话、合同和附件、审查/报告/对话、规则草稿及不可变候选、审批发布与审计历史。浏览器输入、用户自填姓名、请求体中 actor/role、转发头、规则文本均不可信。浏览器 → 应用、账户库 → 合同库、普通用户 → 管理权限、草稿 → 已发布规则均是不同边界。

## 威胁与控制

| 威胁 | 控制与验收 |
|---|---|
| 密码泄漏、批量猜测 | 每人独立盐和内存困难哈希；不记录明文、重置令牌或会话值；失败速率限制、统一错误及恢复方案，生产前压测资源预算。 |
| 会话固定或盗用 | 高熵随机服务端会话、仅存摘要，登录更新会话；HTTPS、HttpOnly/Secure/SameSite、空闲及绝对过期；注销/停用/降权立即撤销。 |
| 伪造审核人或越权 | 服务端从已认证会话取不可变用户 ID，逐次读取当前角色/状态；拒绝客户端提供 actor/role；默认拒绝。用户允许管理员自审，记录提交人与审核人并明确标记自审。 |
| 合同 ID 被猜到或换人 | 列表、详情、导出、提问、异议、附件和草稿逐对象校验所有权/授权；管理员不天然获得所有合同内容；无主旧数据不得自动分配。 |
| 跨站请求、代理伪装 | 所有状态变更检查 CSRF token 和可信来源；生产仅 HTTPS、明确可信代理；环回直连试用不能经代理或公网启用。 |
| 审批后替换内容或抢先发布 | 候选、基线、测试结果、审批绑定完整摘要；修改使审批失效；原子比较并切换；发布和回滚写不可篡改或可检测篡改的审计。 |
| 数据过期误留存 | 审批账本不复制合同原文；审计保留期、访问范围和备份清理另行明确。SQLite DELETE 不等于备份/磁盘彻底清除。 |
| 首个管理员被劫持或锁死 | 禁止公开自注册/默认口令；引导只能由可信本机操作；禁止停用或降权最后一名有效管理员；重置与应急恢复需另行设计。 |

## 必测反例

错误密码、无用户枚举、过期/注销/停用/降权会话、并发引导、最后管理员保护、普通用户和管理员跨角色访问、客户端伪造 actor 与 role、管理员自审的正确留痕、跨站写、暴力重试、跨人审查/报告/问答/附件、候选或基线变更后旧审批失效、并发发布和回滚。每个上线阶段明确已覆盖与未覆盖；不以本机测试替代独立安全审核、数据迁移及 HTTPS 生产验收。
