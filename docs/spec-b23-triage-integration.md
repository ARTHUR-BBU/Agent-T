# B2-3 批3 施工卡：分诊台接线（v0.1 草案——待用户复批后开工）

> 上游：设计稿 spec-b23-classification-gold.md v1.2（硬接口已锁）+ Jev 阈值分析 v0
> 范围：把「建议品类」逻辑接进生产上传路径。模型只建议，永不切换（spec-b2 §3.1）。

## 1. 交付物

1. **分类服务模块** `app/services/category_suggest.py`：调 GLM（主）/Jev（对抗，开关控制），
   输入=生产解析文本，输出=建议品类+置信度，八字段留痕进 llm_call_log 扩展字段
2. **路由逻辑**（上传路径，上传后预审前）：
   - 建议与用户选择一致 → 照常审查（留痕，无感知）
   - 不一致（任何置信度）→ `category_confirm` 响应（现有预审分诊台响应结构复用）
     - 高置信文案：「检测到疑似 {建议品类}」+二选一
     - 低置信文案：强调「建议置信度低」+「按原品类继续」预选
   - 建议=other/低置信+用户选四收类 → 照常审查+报告头「品类存疑」非阻断提示
3. **外部模型开关**：env 开关默认关（关=完全跳过建议逻辑，行为与现状一致）；
   开关开时最小化传输（只发分类所需片段——文本头部+尾部，同校准截断策略）
4. **拒收话术**（老钱签认口径）：「您上传的合同疑似 {品类}，本产品当前支持采购/租赁/
   保密协议/技术服务四类，暂不在支持范围」——接进现有 unsupported 分支

## 2. 非目标（本批不做）

- 不自动切换品类/清单（永远）
- 不做附件「存在性」断言（附件金标另批）
- 不动 65 格规则引擎与评分路径（LLM 不盖章红线）
- Jev 不进生产（对抗候选，仅校准对比；生产主通道=GLM，故障降级=跳过建议）

## 3. 测试要求

- 对抗集：建议一致/不一致高置信/不一致低置信/other 兜底/开关关闭五态
- 开关关闭=零外部调用（断言无网络请求）
- 留痕八字段完整性断言
- category_confirm 复用现有响应结构（前端零改动或最小改动——开工前与阳仔对线框）
