# B2-3 批3 施工卡：分诊台接线（v0.2——用户已复批开工 2026-10-17）

> 上游：设计稿 spec-b23-classification-gold.md v1.2（硬接口已锁）+ Jev 阈值分析 v0
> 范围：把「建议品类」逻辑接进生产上传路径。模型只建议，永不切换（spec-b2 §3.1）。

## 1. 交付物

1. **分类服务模块** `app/services/category_suggest.py`：调 GLM（主）/Jev（对抗，开关控制），
   输入=生产解析文本，输出=建议品类+置信度，八字段留痕进 llm_call_log 扩展字段
2. **路由逻辑**（上传路径，上传后预审前）：
   - 建议与用户选择一致 → 照常审查（留痕，无感知）
   - 不一致（任何置信度）→ `category_confirm` 响应（现有预审分诊台响应结构复用）
     - 高置信文案：「检测到疑似 {建议品类}」+二选一
     - 低置信文案：强调「建议置信度低」+「按原品类继续」预选
   - 建议=other/低置信+用户选四收类 → 照常审查+报告头「品类存疑」非阻断提示
3. **外部模型开关**：env 开关默认关（关=完全跳过建议逻辑，行为与现状一致）；
   开关开时最小化传输（只发分类所需片段——文本头部+尾部，同校准截断策略）
4. **拒收话术**（老钱签认口径）：「您上传的合同疑似 {品类}，本产品当前支持采购/租赁/
   保密协议/技术服务四类，暂不在支持范围」——接进现有 unsupported 分支

## 2. 非目标（本批不做）

- 不自动切换品类/清单（永远）
- 不做附件「存在性」断言（附件金标另批）
- 不动 65 格规则引擎与评分路径（LLM 不盖章红线）
- Jev 不进生产（对抗候选，仅校准对比；生产主通道=GLM，故障降级=跳过建议）

## 3. 测试要求

- 对抗集：建议一致/不一致高置信/不一致低置信/other 兜底/开关关闭五态
- 开关关闭=零外部调用（断言无网络请求）
- 留痕八字段完整性断言
- category_confirm 复用现有响应结构（前端零改动或最小改动——开工前与阳仔对线框）

## 4. 前置条件

- 用户复批本施工卡
- 阈值表定稿（GLM 补考+用户复批，见 threshold-analysis-jev-r1.md §4）——
  接线可先开工（开关关闭不影响现状），阈值作为配置项后补

## v0.2 变更注记（2026-10-17，实施期裁定）

1. **§1.2 条 3 旧文案作废**：v0.1 草稿「低置信+四收类→照常+存疑提示」与设计稿
   v1.2 已批红线（所有不一致一律 category_confirm）冲突，**以设计稿为准**——
   实现为「所有不一致一律弹窗，置信度 tier 只改文案与默认选项」。
   other 兜底照常放行不变。
2. **主通道选型变更（用户拍板 2026-10-17）**：GLM-4-Flash → **TypeSafe Jev**
   （计费实锤 $0.041/M + 双模型对比 29/29 vs 24/29）。GLM 免费档降为校准对照，
   不进生产。transport 经 llm_client.typesafe_judgment 单点（账本纪律延伸）。
3. reject_notice（拒收话术）保留为公共函数（测试锁定口径），当前 unsupported
   分支由预审层承接，建议层不对四收类用户弹拒收——语义接线随品类开放推进。
4. **挂账（肉饼 P2-B）**：解析失败（parse_failed）时账本 outcome 仍记 success
   ——LLMCallRecord schema 无 raw 字段，transport 层无法感知下游解析结果；
   处置=建议层 SuggestOutcome.skip_reason 留痕（调用侧可查），账本细分随
   存量节点统一改造（与 chat_completion 同款缺口一并修）。
