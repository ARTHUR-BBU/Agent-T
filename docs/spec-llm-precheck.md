# Spec：LLM 预审（合同分类 + 支持性判断）

> 状态：草案 v1（待老钱金标 + 小智娘测试计划 + 肉饼红线评审）
> 提出人：用户（2026-09-09，实测发现服务合同按采购清单硬审产出荒谬结论）
> 负责人：开发狗

## 1. 背景与问题

当前流水线：用户上传时自选品类 → 规则清单逐条审 → LLM 参考评分。
系统**无条件信任用户选的品类**。用户在「采购」下传了一份「AI 故事视频
制作服务合同」，系统硬审，产出「未找到标的 / 缺价款与支付约定」——
看似专业，实则文不对题（垃圾进、垃圾出，且穿着专业外衣）。

## 2. 目标

上传后、审查前插入 LLM 预审环节：

1. **识别**：这是什么合同（输出类型判断 + 依据）
2. **判断支持性**：我们是否支持该类型；不支持 → 明确告知支持列表，绝不硬审
3. **对账**：与用户所选品类不一致 → 提示用户确认切换，**不静默切换**
4. **预判底稿**（二期）：预审摘要进入评分上下文，让参考分更有依据

## 3. 方案

### 3.1 流水线变化

```
upload → extract_text → [NEW] precheck → 对账分支 → run_checklist → ...
```

precheck 同步执行（v4-flash 单轮实测 2-3s，上传仍秒回量级；
异步审查机制不变）。

### 3.2 precheck 模块（app/services/precheck.py）

- 输入：合同全文（clip 到 ~3000 字，分类不需要全文）
- 输出（Pydantic Schema 校验，禁止裸 json.loads）：

```json
{
  "detected_type": "服务合同（视频制作类）",
  "is_supported": false,
  "suggested_category": null,
  "confidence": "high | medium | low",
  "summary": "一份委托制作短视频的服务合同，核心义务是交付成片…"
}
```

- 供应商链复用 llm_ask（DeepSeek > 智谱 > xAI）；无 Key 或调用失败 →
  **降级跳过预审**（见 3.5），流程照旧
- 提示词进 `app/prompts/`（提示词管理约定），输出 JSON + Schema 校验，
  解析失败重试一次，再失败降级

### 3.3 对账分支

| 情形 | 行为 |
|---|---|
| 检测=所选 或 置信度低 | 照旧开审（置信度低时不打扰用户） |
| 不支持 | 返回 `category_confirm` 响应（不开 review），前端展示「检测到 XX 类合同，暂不支持；目前支持：租赁/采购/NDA」 |
| 支持但不一致 | 返回 `category_confirm` + 建议品类，前端二选一：「按原品类审 / 切换为 XX」；用户确认后带最终品类重新进入审查 |

API 形态：`POST /api/upload` 响应增加分支（200 + `status:"category_confirm"`，
无 review_id；确认后重新 POST 同一文件 + 最终品类）。保持无状态，
不加确认端点。

### 3.4 红线兼容性论证（供肉饼评审）

- 分类/路由 ≠ 裁判：LLM 决定「用哪把尺子」，档位仍 100% 出自
  run_checklist；预审结果**永不写入 items/status**
- 预审 summary 若展示，标注「AI 预判」并走禁语清洗
- 降级路径（无 Key/解析失败）退回现状，规则审查可用性不受影响——
  预审是增强不是依赖（此为 fail-open，特此声明请肉饼裁决是否接受）

### 3.5 降级矩阵

| 情形 | 行为 |
|---|---|
| 无 LLM Key | 跳过预审，照旧开审 |
| 调用超时/异常（重试 1 次后） | 同上 |
| JSON 解析失败 ×2 | 同上 |
| 置信度 low | 视为「检测=所选」，不打扰 |

## 4. 影响范围

- `app/api/routes.py`（upload 分支）、`app/api/schemas.py`（响应模型）
- 新增 `app/services/precheck.py` + `app/prompts/precheck.py`
- 前端 `app.js`（category_confirm 交互）
- 测试：precheck 单测（mock LLM）+ 跨品类对抗集（小智娘）+ 全量回归

## 5. 验收标准

1. 服务合同传采购：用户收到「暂不支持/建议切换」提示，**不产出错误报告**
2. 正确品类：行为与现状完全一致（预审不增加误打扰）
3. 无 Key 环境：行为与现状完全一致
4. 全量测试绿 + 对抗集通过率达标（标准由小智娘定）
5. 老钱金标案例全数命中

## 6. 二期（本 spec 不实现）

- 预审 summary 进评分提示词
- 支持新品类（服务合同等）——老钱评估清单可行性后另行立项
