## 一、验尸方法

对每份证物合同，四层对照取证：

1. **生产路径确认**：Dockerfile.server 明确不装 docling（torch 系 2G+，服务器扛不住，`Dockerfile.server:3-4`）→ 生产抽取路径 = python-docx 回退路径，与本地验尸**同一条路径**，无「Docling 形态差异」变量。
2. **原始结构取证**：python-docx 直接遍历 body 一级段落+表格，逐块编号。
3. **抽取文本取证**：跑 `app/services/extract.py::extract_text`（生产同函数），定位金标关键词落点。
4. **引擎判定取证**：跑 `checklist.run_checklist`（生产同入口），取标的/保密项判定。

## 二、逐证物结论

### 2.1 food-procurement-xinjiang-2025（标的漏报坐实证物）

- 抽取文本含表格表头 `序号→材料名称→技术及质量要求`（T124 块），**抽取层完整读到**。
- 引擎 `subject_matter`（标的）判定=未找到。
- **根因：词表缺口，非抽取缺口。** 标的项 pass 词表仅 5 词（型号|规格参数|配置清单|技术参数|产品规格，`checklist_procurement.yaml:93-99`），全是办公设备味；金标标的语义域 12 词（品名|材料名称|货物名称|标的物|项目名称|承揽项目|服务内容|服务范围|工作内容|质量标准|技术标准）**一个都不在 pass 词表里**。
- ⚠ **附带发现（假命中风险）**：food 全文唯一的「标的」二字是「凡是超**标的**蔬菜水果品种严禁配送」——「超标+的」跨词假命中。金标验尸 v1 记录的「标的字样仅存在于表格文本」实为此假命中。**扩词表时必须防跨词组合**（「超标的」不得当标的信号）。

### 2.2 work-contract-gf-2000（承揽项目+保密 双坐实证物）

- 「承揽项目」在 P06（第一条标题）、P13（第六条）——**正文段落，不在表格**。金标 v1「承揽项目在表格」归因不成立。
- 「保密」在 P11（第四条「定作人提供技术资料、图纸等的时间、办法及**保密要求**：」）——**正文段落**，且冒号后**留白**。
- 引擎 subject_matter=未找到（同 2.1 词表缺口：「承揽项目」不在 pass 词表）；confidentiality=未找到（词表五词：保密条款|保密义务|保密责任|应当保密|负有保密，无「保密要求」）。
- **根因：两项都是词表缺口。** 保密项另有一个法务问题需老钱裁定：「保密要求：」空壳标签（内容留白）算不算义务性表述？与 NDA 侧空壳标签挂账同族。

### 2.3 cement-sale-gf-2008（观察点：品名/规格是否在表格被漏读）

- 全文 21 块中 17 块为表格行，但逐行核验**全部为空白栏位**（43 处含数字的行全是「第＿种方式解决」类模板留白字），品名/规格/牌号在任何层级都不存在。
- **观察点关闭：纯空白模板，subject_matter=未找到是合理判定**（符合金标「明示不修：空白留白模板全项未找到」口径），不是抽取漏读。

## 四之二、T4 合并单元格去重评估结论（A2 补记，只评估不动代码）

**量化实测**（重复字符/该表总字符）：zhejiang 92.1%、cement 91.3%、合计 5 份 89.3%——膨胀率**远超预想**，重灾区抽取文本近九成是重复。

**定性**：对 YAML 正则判定层**无影响**（重复=命中冗余，词表有即中，不依赖唯一性）；真实成本在 **LLM 审查层信噪比**（model_review/评分卡拿到的文本被重复淹没，token 浪费+重点稀释）。

**结论：本批不做。** 理由：去重必须改 `_table_text_parts`（生产抽取主路径），会移动文本位置→触碰 hit_alternatives 豁免门与 procurement_term 窗口的坐标语义——P2 教训「窗口化搜索必须验长文本」，坐标类改动风险收益比极差。收益=省 token，风险=三条已验证判定链路坐标漂移。

**挂账观察**：若未来出现「重复文本导致 LLM 审查漏检/窗口错位」实锤案例再立项；立项时优先考虑「只对 LLM 输入层去重、规则引擎保持原文本」的分层方案（坐标链路零触碰）。
