# Claude Code 交接：账户与规则审核开发前

用户要求继续开发规则的真实启停、具名审核、正式发布和回滚，并提出普通账户与管理员审核账户。生产部署仍按用户先前安排留待 Claude Code；本轮仅在本机开发，不覆盖已有工作区和试用数据库。

现有 Basic Auth 仅是一套可选的共享密码，不形成真实个人身份；审查、报告、异议和草稿没有完整个人/组织隔离，手填的评审人姓名不是认证身份。因此先建立账户、服务端权限及资源归属，再让审批、测试、版本和发布绑定到真实身份与不可变内容；不将新增入口直接开放公网，也不把历史自报姓名转换成正式审批。

计划保留普通用户与管理员两种用户可见角色；管理员的账户管理、审核与发布能力在服务端分别检查。用户明确允许管理员审核自己提出的规则，须明确标记提交人与审核人为同一人的情况。各阶段须独立审核和反向越权测试，正式发布需单独的完整版本、不可变测试证据、授权和回滚机制。
