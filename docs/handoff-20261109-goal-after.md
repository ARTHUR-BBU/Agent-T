# Claude Code 交接：规则与用户管理继续开发

2026-11-09。目标仍为完成规则管理和用户管理，用户允许管理员自审，暂不部署。保留现有未提交改动及试用数据库。

## 本次进展

- 本机账户试验增加本人修改密码和管理员重置他人密码；均验证本人密码、重查会话、撤销受影响用户的所有会话并记账户审计。管理员创建或重置的临时密码 24 小时有效，首次登录只能改密或退出；最后管理员保护不把临时管理员当作可用管理员。哈希复用有界计算槽。已有旧账户库因缺少可信临时密码状态而明确拒绝启动，需另行设计迁移。
- 新增默认隐藏的本机账户管理试用页面，接口启用后可登录、改密、创建账户、启停、修改角色和重置密码；页面明确提示合同数据尚未隔离。该页面和 API 仅限直接环回试用，不是正式多用户登录。
- 规则快照支持受控 enabled 布尔值，停用项不参与新审查；禁止停用硬性项，发生停用的评分分段须保留至少一个启用、非 NA 且无条件门控的常规项。草稿目录展示启停状态并支持提交重新启用建议；草稿仍不改变生效规则。
- 候选与原基线对比，禁止删除重排、修改硬性项、注入任意复杂正则；新增项仅允许字面关键词，名称和说明校验类型及长度。
- 新增账户库内的不可变规则版本记录和活动指针基础。`RuleReviewLedger(..., versioned=True)` 在同库写事务读取活动指针并核对候选基线；指针增加递增代次，避免版本 A→B→A 时旧候选审核重新有效，文件模式的候选不能当作版本化候选审核。旧试验库缺字段时显式拒绝，不做静默迁移。初始化仅由管理员导入当时文件内容；数据库版本目前**尚未接管真实引擎**，也没有开放发布或回滚操作。

## 审核与剩余工作

独立审核复现并协助修复“分段只剩不适用项却被打满分”的停用风险，以及密码哈希计算可被滥用的问题；停用规则后，结果及报告仍须显示停用范围和评分变化提示。

正式功能仍需：账户恢复及正式身份接入、合同和所有衍生接口的数据隔离；草稿与认证身份衔接；候选级真实测试证据；活动指针的权限、审批、测试与原子发布/回滚；规则目录、上传预审、立场提示、历史报告、在途审查统一消费冻结版本，保留完整摘要和历史字节。首次文件导入与并发文件修改不能原子协调，切换前需解决单一数据源和所有入口的部署顺序。旧试验表无通用迁移，Cookie 跨端口隔离、HTTPS 等也未解决。

本次测试和独立审核的最终结果以对用户报告及命令输出为准；未做部署，不能将局部回归解释为生产就绪。

账户页面真实本机浏览器联动测试已覆盖管理员建用户、临时密码首次登录、改密及重新登录。独立审核复测了跨标签页 CSRF、失效会话及迟到响应；本机 Cookie 仍不按端口隔离。执行留痕当前只有 12 位内容摘要，且磁盘源码哈希不能证明已加载代码版本，正式发布前须使用完整内容摘要和不可变构建标识。全量回归需以最终稳定代码重新执行并记录最终结果。

## 本机账户试验启动示例

下例只使用虚构账户和独立测试数据库。先创建一个空目录，例如仓库内的 `trial-db`；首位管理员账号和密码由操作人自己选择，密码在交互提示中输入，不写在命令行。不要把试验接口暴露到公网或放在反向代理后。

```powershell
$env:ACCOUNT_LOCAL_ENABLED = '1'
$env:ACCOUNT_DB_PATH = (Join-Path (Get-Location) 'trial-db\accounts-goal-local.sqlite')
$env:STORE_DB_PATH = (Join-Path (Get-Location) 'trial-db\accounts-goal-review.sqlite')
python -m app.services.account_bootstrap --db $env:ACCOUNT_DB_PATH --username admin --name '管理员'
python -m uvicorn app.main:app --host 127.0.0.1 --port 8028
```

通过 `http://127.0.0.1:8028` 进入账户管理试用；首位管理员只能初始化一次。试用数据隔离只覆盖账户数据库，合同数据尚未按账户隔离。测试完毕自行停止服务；不要覆盖已有试验文件。
