# 附录 B：粘贴文本审查后端设计（codex 十三轮批示：C0 开工前定稿）

## 1. 入口与互斥

- 复用 `POST /api/upload`（multipart）：`file` 改为可选（`File(None)`），新增 `pasted_text: str = Form("")`
- **互斥**：file 与 pasted_text 同时出现 → 422「文件与粘贴文本只能二选一」；两者皆无 → 400「请上传文件或粘贴合同文本」
- 前端两入口卡互斥切换（线框 §4），后端不信任前端、独立校验

## 2. 校验（后端独立，不依赖前端）

| 检查 | 规则 | 失败响应 |
|---|---|---|
| 空白 | strip 后为空 | 400「粘贴内容为空」 |
| 超限 | strip 后 >200,000 字符 | 413「超出 20 万字符上限，请删减后提交」（**不截短续审**——合同尾部常含免责/争议条款） |
| 品类/立场 | 与文件模式同一校验（422） | 不变 |
| 限频 | `upload_rate_limit` 依赖不变 | 不变 |

## 3. 归一化与流水线复用

- 文件名占位：`粘贴文本_{YYYY年MM月DD日}.txt`（历史列表/报告/结果态与文件模式完全同权，无二等标记）
- `raw = text.encode("utf-8")`；**免解析**：纯文本已是解码文本，`contract_text = text` 直接就位——不占解析槽（`_parse_slots`），预审分诊/品类建议照常跑（它们只消费 contract_text）
- 其后全部流水线（预算/trace/worker/并发槽/TTL 保留/报告）与文件模式**逐字节同路**——粘贴审查没有任何降级或二等通道

## 4. 复用防线清单（codex 十二轮 P1-3 要求逐项落实）

| 防线 | 落实 |
|---|---|
| 预审分诊 | 照常触发（含 precheck dialog 品类确认） |
| 限频 | upload_rate_limit 依赖原样 |
| 并发闸 | review 槽位 worker 原样；解析槽不涉及（免解析） |
| 费用闸 | review budget/suggest budget 原样；费用表登记粘贴模式同文件模式口径 |

## 5. 前端配套（C2 实施）

- 粘贴卡展开 textarea（<200 字置灰提示「内容太短」；20 万字符超限**保留输入、禁用提交、行内报错**）
- 两入口互斥切换；选择任一入口后审查设置区（品类/立场/铁律旁注）才出现
