# Claude Code 交接：候选回归进程树基础能力

## 已实现

- 新增内部 Windows Job Object 运行器。启动器在获得 Job 分配前等待握手，使用 `-I -S` 避免启动前加载用户 site；Job 关闭时清理其受控进程。标准输出和错误输出丢弃，不依赖可能被子进程持有的管道。
- 返回实际退出码、超时及父进程退出后仍有子进程被中断的标志；调用者不能把存在中断的工作当作通过。超时从 Job 分配和握手后开始，不覆盖启动前全部耗时。
- 测试正常和非零退出、超时、目标父进程提前退出、监管进程被杀、大量输出，以及受控子进程独占文件在返回时可以再次独占打开。

## 验证

- Windows 本机、隔离临时数据库：`python -X utf8 -m pytest -q tests/test_regression_process.py`：6 passed in 24.55s，退出码 0。
- `python -m ruff check app/services/regression_process.py tests/test_regression_process.py`：通过。
- 独立审核发现并推动修复了残留子进程被中断却仅返回成功码的问题；也指出仍不能以单次 Job 活动进程数归零证明所有资源普遍释放。

## 未完成与边界

- 运行器目前未接入现有 `run_gold_checks` 或完整候选回归。旧金标入口仍使用 `subprocess.run` 和输出管道，超时后不能据本轮结果推断其子进程树已安全清理。
- Job 计数和本轮单个文件探针不是所有进程句柄、所有异步 I/O 或所有目录资源的释放证明。接入实际回归前，仍需定义工作区资源核验、无法确认时保留目录、故障注入及清理失败处理；不能把结果直接作为发布证据。
- 仅支持 Windows；其他平台明确拒绝而非假装受控。Job 不是安全或网络沙箱，不能控制由 Job 外的系统服务创建的进程，也未限制密钥及网络。真实模型、生产环境和本轮代码的全量回归尚未验证；没有部署。
