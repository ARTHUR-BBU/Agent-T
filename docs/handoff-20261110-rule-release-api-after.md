# Claude Code 交接：规则发布与回滚接口阶段结果

## 已实现

- 新增默认关闭的本机试验发布、版本历史和回滚接口；仅在 `RULE_RELEASE_LOCAL_TRIAL=1` 且账户上传试验整体启用时可用。执行者需为已登录管理员，执行过程校验本机来源、CSRF、版本代次和请求幂等，并保留具名审计。
- 发布请求携带页面预期候选摘要，并仍需匹配最新品类测试、审核及完整候选回归记录。现阶段没有真实完整回归记录生成器，故没有可对用户展示的发布按钮；不得手工伪造证据。
- 规则审核页面可查看最近本机试验版本事件、选择曾生效版本并填写理由回滚。回滚仅影响后续新发起的试验审查。回滚成功但刷新失败会明确提示并暂时禁用重复操作。
- 独立审核未发现本轮确定性严重权限绕过；指出的历史截断和刷新失败提示已修正。

## 验证

- 隔离临时数据库、禁用真实模型密钥：`python -X utf8 -m pytest -q tests/test_local_rule_release_api.py tests/test_rule_release.py tests/test_local_rule_management_api.py tests/test_rule_review_frontend.py`：13 passed in 60.37s。包括管理员/普通用户、CSRF、缺回归证据拒绝、摘要错误、幂等、过期代次、发布和回滚事务，以及浏览器回滚提示。
- 上述发布成功用例中的完整回归记录是测试代码构造的合成数据，仅验证门槛和事务，不证明真实候选通过完整回归。
- `node --check app/static/rules_review.js` 与相关 Python 文件 Ruff 检查均通过。

## 未完成与限制

- 缺可信完整候选回归生成、发布页面、可信不可变构建和完整回归验收；目前不能声称规则正式发布闭环已完成。现有本机源码摘要存在文件变更竞态，不是签名构建证明。
- 页面最多展示最近 100 条事件和版本并提示截断，尚无分页；更早的版本不能从页面选择。尚未验证真实候选完整回归、生产环境及最新全量回归；没有部署。
- 账户合同功能仍为试验，只读结果之外的导出、问答等需接入权限；任务恢复坏数据整批阻塞等问题仍待处理。
