# B7-6 整壳改版线框：Gemini 式工作台（阳仔 · 定稿 v1）

> 依据现状：app/static/index.html（三屏）、app/static/styles.css（480px 单断点 + B7-5b 1024/1280 双断点）、app/static/app.js（show() 三屏切换、hash 路由 #/review/{rid}[/item/{key}]、mqMobile/mqDesktop 节点搬迁先例、jumpToItem、fillAskContext）、docs/design-tokens.md v0.1、wireframe-b75b-desktop.md、spec-b75a-ai-findings.md、tests/test_frontend_e2e.py 断言依赖面（已逐条核对）。

## 0. 一句话讲给老板 + 设计立场

以前的页面像「一间房一个用途」：上传一间房、结果一间房、问问题再去第三间房。改版后是一间**大工作室**：左手边一个抽屉柜（左栏，上层放历届档案=历史审查，下层放当前这份合同的目录=条目导航），右手边一张大桌面（右工作区，合同摊开、便签本在手边、聊天就在便签本背面）。去哪屋都省了，伸手就够着。

设计立场（延续 M2 信任感三原则）：
- **换壳不换魂**：档位语言（通过/需关注/未找到/不适用）、黄底命中词、虚线参谋家族、评分灰字铁律——一个都不动，只给它们搬进新房子
- 左栏是**目录**不是**第二个结果页**：每条导航项点了都是「滚过去+选中」，不复制内容
- 零动画框架；动效只有既有 is-flash + 150ms 开合过渡（v0.2 成文）

## 2. 左栏两分区明细

比喻：上区是**档案室的目录柜**（每审过一份合同立一张卡），下区是**摊开这份合同的目录页**（翻到哪条，目录上就标到哪条）。

### 2.1 上区：历史审查记录

**「+ 新审查」主按钮**（区首，--radius-pill 全宽胶囊，accent 底白字，44px 高）——Gemini 的「New chat」对应物，点它回空态。

每条历史条目（横向卡片，52px 行高）：
```
┌──────────────────────────────┐
│ 采购合同-A公司_v3.docx        │  ← 主行，--type-side 14px，超长省略号
│ 采购合同 · 11月5日   ● 已完成 │  ← 次行，caption 13px 灰；右侧状态点+字
└──────────────────────────────┘
```
- 状态点语义（小圆点 8px + 文字双通道）：已完成=中性灰点 / 审查中=accent 蓝点 / 失败=danger 红点。**不占用档位琥珀**——琥珀留给「需关注」，避免「这份合同有风险」和「这份还没审完」混一个色
- 点击 ⇒ 加载该审查进工作区（复用既有 GET /api/review/{rid} 渲染链），hash 写 `#/review/{rid}`（既有路由保留），当前条目高亮 `--color-selected-bg`
- 空态：caption 灰字「还没有审查记录，点上方按钮开始第一份」
- 依赖后端小刀：新增 `GET /api/reviews?limit=50`（返回 id/文件名/品类/时间/状态；粘贴文本审查的记录文件名占位「粘贴文本_11月6日」）

### 2.2 下区：当前合同内导航

仅当工作区有打开的审查时渲染；没有则整区隐藏（不显示空壳）。

```
本份合同 ─────────────
 ○ 概览              → 滚到 meta 卡
 ○ 清单  通过4 · 需关注3 · 未找到1   → 滚到图例/清单顶
   ├ 付款条件        [琥珀点]  → jumpToItem 选中+滚动
   ├ 违约责任        [琥珀点]
   └ （>8 条折叠「展开全部」）
 ○ AI 发现  2 待确认   → 滚到面板；待确认子列表前 5 条同名规则
 ○ 对话  12 条        → 滚到对话工作台并聚焦输入框
 ○ 评分              → 滚到评分卡并展开
```

- 全部是**锚点跳转**（复用 jumpToItem / scrollIntoView，禁止 smooth——零动画纪律），不复制内容进侧栏
- **双向同步**：清单里选中某条 ⇒ 侧栏对应项高亮；侧栏点某条 ⇒ 清单选中该条。一处状态两处亮，人不会迷路
- 下区不显示「通过」条目子列表——通过的条目没有操作价值，列出来只会把目录撑厚（克制）

## 3. 右工作区三态

### 3.1 空态（ws-empty = 原上传页融入）

对话式引导，不再是「一张表单」：

```
│                                                      │
│   🤖 把合同交给我，我来逐条核对。                      │  ← 引导气泡（白卡）
│      PDF、Word 都行，也可以直接粘贴文本。              │
│                                                      │
│   ┌─────────────────┐  ┌─────────────────┐           │
│   │ 📄 上传合同文件   │  │ 📋 粘贴合同文本   │           │  ← 两张入口卡
│   │ 点选或拖入文件    │  │ 复制正文直接开始  │           │
│   └─────────────────┘  └─────────────────┘           │
│   （选择文件或点开粘贴后，下方出现 ↓）                  │
│   [文件胶囊：采购合同-A.docx ×]  或  [粘贴文本框]       │
│   合同类型 [采购▾]   我代表哪一方 [买方|卖方|中立]       │  ← 品类/立场原样平移
│   立场只影响解释，不改变清单通过/需关注等规则档          │  ← 铁律旁注常驻不动
│   [        开始审查        ]                          │
│   ⚠️ HTTP 红线警示（原文不动）                          │
│   隐私说明（原文不动）                                  │
```

- 品类/立场/铁律旁注/HTTP 警示/隐私说明五个既有元素**逐字平移**，一个不丢——它们是信任感的地基
- 两个入口卡共用同一张「审查设置」区：先选文件或先展开粘贴框，设置区才出现（没选东西时不摆空表单，引导感更强）；品类预审弹窗（precheck dialog）流程不变
- 占位文案过九哥后定稿

### 3.2 审查中（ws-running）

现有三段真实进度清单（预审分诊→规则扫描→AI 评分→AI 观察）**原样平移**，居中放工作区。侧栏对应历史条目同步显示「● 审查中」。无 spinner 无百分比的红线不变。

### 3.3 结果态（ws-results）

```
┌ ws-inner ──────────────────────────────────────────────┐
│ meta 卡（文件名/统计/立场胶囊/导出）——全宽不动            │
│ ┌ col-main ──────────────┐  ┌ col-side（sticky）──────┐ │
│ │ facts / 图例 / 清单     │  │ 详情头 → 说明 → 原文(黄底)│ │
│ │ AI 发现面板             │  │ 三卡（改建议/选定/牵连）  │ │
│ │ 异议面板                │  │ [问清楚一点 ↓]           │ │
│ │ 评分卡（折叠沉底）       │  │ ┌────────────────────┐ │ │
│ └────────────────────────┘  │ │ 对话工作台           │ │ │
│                             │ │ 「关于：付款条件」     │ │ │
│                             │ │ 🙋 违约金 30% 合理吗？│ │ │
│                             │ │ 🤖 四段式答案…       │ │ │
│                             │ │ [输入框        ][发送]│ │ │
│                             │ └────────────────────┘ │ │
│                             └────────────────────────┘ │
└────────────────────────────────────────────────────────┘
```

**对话工作台的家（关键决策）：右栏便签本下半段，详情之下。**
- 讲给老板的版本：便签本正面写的是「这一条怎么看」，翻到背面接着聊——聊天的上下文（说明/原文/三卡）就在同一屏，不用来回翻页
- 「问清楚一点 →」点击 = 滚动到对话块 + 输入框聚焦 + 自动带上「关于：××条目」标签；B7-5b 的 ask-dialog 与 #screen-ask **退役**，但 ask 的家底全部平移：四段式答案渲染、chips、seq 判废、立场文案——渲染函数换宿主不换逻辑
- 每条用户消息头顶 caption「关于：付款条件」（--type-caption 灰）；助手消息复用四段式卡片；持久化+刷新恢复由同批施工方提供端点，UI 按「消息数组」渲染
- 报告收录对话：纯后端行为，UI 零改动
- **备选方案 B（记入文档备而不做）**：若试用反馈右栏内聊太挤，对话块可切换为全宽沉底 section（CSS 一行改挂载点），布局决策留了后路

<1024 时对话工作台随单列流自然排在三卡之后（col-side 搬迁机制自动覆盖）。

## 4. 粘贴文本审查入口交互流

```
点「📋 粘贴合同文本」卡
  ⇒ 卡片原位展开为 textarea（min-height 160px，placeholder：「把合同正文粘贴到这里」）
  ⇒ 右下角实时字数（caption 灰）：<200 字置灰提示「内容太短，像是没贴全」；上限 20 万字符，超限截断+行内 .error 提示（既有样式）
  ⇒ 审查设置区（品类/立场/铁律旁注）滑入出现
  ⇒ 「开始审查」⇒ 走既有 /api/upload 流程（multipart 增加纯文本模式：后端小改，无文件名记录占位「粘贴文本_日期」）
  ⇒ 预审分诊 dialog 照常触发（粘贴文本一样要做品类确认）
```

- 粘贴后再次点击「📋」卡可收起换回文件入口（两入口互斥切换，不并存——同时来两份会乱）
- 粘贴文本与文件审查在历史记录、结果态、对话、报告里**完全同权**，UI 无任何「这是粘贴的」二等标记（用户不需要知道区别）

## 6. 移动端抽屉交互细节

| 项 | 规格 |
|---|---|
| 开 | 顶栏汉堡按钮（44px 触控目标，aria-label="打开导航菜单"，aria-expanded 同步） |
| 关（四通道） | 点遮罩 / 再点汉堡 / Esc / 点任意导航项后自动关（历史项必关；下区锚点项跳转后也关） |
| 遮罩 | `--color-backdrop`（既有 token），点击关闭；遮罩不进 history |
| 动效 | transform translateX(-100%)→0 + 遮罩 opacity，`--dur-move` 150ms；`prefers-reduced-motion` 时直接显隐（既有先例） |
| 焦点管理 | 开 ⇒ 焦点进抽屉第一条目；抽屉开着 ⇒ 右工作区+顶栏设 inert；关 ⇒ 焦点归还汉堡按钮。焦点圈定不倒退（对应 dialog 的 showModal 先例） |
| 背景滚动 | 抽屉开着时 body overflow hidden |
| 当前态指示 | 当前审查的历史条目高亮 `--color-selected-bg`；下区当前选中条目同桌面规则——抽屉开着时看得到「我在哪」 |
| 返回键关抽屉 | 不做（history 状态机复杂度不值；点遮罩已是单手动作）——挂 C3 备选 |
| <480 专属 | 无（这就是本次统一的意义：<480 与平板带同一套抽屉，不再有独立单列+hash 详情页） |
