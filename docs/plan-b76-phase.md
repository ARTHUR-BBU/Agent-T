## 一、背景与问题清单（试用反馈原文归纳）

1. 跨源跳转文案绕（「看这条规则」「看清单中的这条」需两次脑补）
2. 「对您的影响」观点类无 AI 修改/补充入口（保守裁定过严）
3. 「未找到」条目是死条目（只有诊断没有药方）+ 与 AI 发现缺双向关联
4. 问清楚是弹窗/跳页，无对话历史，刷新即丢——升级为共享对话工作台
5. 整体 UI 是「手机版拉宽」+B7-5b 双栏补丁——要 Gemini 式左栏+右工作区整体改版
6. 试用追问出的盲区（三视角之外的「写错」类、金标缺失）→ 单列 B7-7 议题，不入本阶段

## 三、技术方案要点

1. **持久化**：对话流=审查单新字段（随单存取，TTL 同审查单）；追加式写入与 ask 现有锁同一把 review 锁（B7-5a 六轮教训：复合操作单锁）；50 轮上限、单条超长截断并在 UI 明示
2. **状态恢复**：GET /api/review/{rid} 返回整条对话流（与三卡恢复同纪律）；前端刷新即还原
3. **报告收录**：新章节「问清楚对话记录」，每轮含所属条目+问答四段式摘要；章节编号条件式顺延（B7-3b 教训：无对话不渲染，字节契约不破）；范围说明文案更新
4. **判废机制零改动**：askReqSeq/REV_STATE 判废是正确性基石，只新增使用点不碰判定逻辑
5. **design-tokens v0.2**：新 token 成体系（阳仔出对照表：新增/废弃/改值），禁止零散加值；动效仅 is-flash 族+必要过渡成文

### 三-补1：共享对话流的能力边界（codex 十二轮 P1-1 写定）

- **历史如何进入模型上下文**：每轮提问仍以「当前条目上下文+本轮问题」为主体（现有 ask_about_item 行为不变）；在此之上附加**最近 N 轮对话摘要区**（N=10、总长封顶 6000 字符，防 token 膨胀），每轮前置来源标注「（关于：××条目）」——跨条目追问时模型能看到前情且知道说的是哪条
- **发送资格门禁不放宽**：必须先选中清单条目（未选条目输入框禁用+提示「先从清单选一条」）；可发范围维持现有 askable 判据（需关注且非补盲）——**观点类、未找到项在 B7-6b/6c 解锁前一律不可发**，跟进批开放时同步改门禁，不在本批放水
- 观点类/未找到在对话流中只读可见（别人问过的相关轮次），不产生新发送入口

### 三-补2：对话存储的并发/重试/额度规则（codex 十二轮 P1-2 写定）

- **每轮一条持久化记录**，字段：`turn_no`（合同内单调递增）、`review_id`、`item_id`、`state`（processing→success/failed）、`question`、`answer`、`created_at/finished_at`；唯一键=(review_id, turn_no)
- **重试不重复入账**：失败轮重试=原 turn 记录状态流转（processing→failed→processing→success），绝不新开 turn；新问题才新 turn
- **50 轮上限在调用模型之前检查**：超限直接拒绝并明示（无费用、无半截记录）；并发竞争由同一把 review 锁串行化
- **归档与页面判废解耦**（关键）：服务端按 turn 归档答案（谁的 turn 归谁），前端 seq 判废只管「当前页面显示哪个」——**甲条回答处理中切到乙条：甲的结果照常归档到甲的 turn，绝不串写乙；用户回到甲条时从持久层读回**
- 验收增补：①第 49 轮后两个并发请求（一个成功一个被拒，不产生半截记录）；②甲条回答中切到乙条（甲归档正确、乙显示不串、返回甲可见）

### 三-补3：粘贴文本审查边界（codex 十二轮 P1-3 写定；附录 B 随施工卡在 C0 前定稿）

- **超限不自动截短续审**：合同尾部常含免责/争议解决等关键条款，截短=静默丢条款。前端保留输入、阻止提交、明示「超出 20 万字符上限，请删减后提交」；后端独立校验（双保险，前端绕过无效）
- 附录 B（C0 开工前定稿）必须写明：文件/文本两入口互斥、空白与超限处理、复用既有预审分诊/限频/并发闸/费用闸四道既有防线


## 四、测试策略（e2e 改造是本阶段最大工程风险）

- **存量**：现有 61 项 e2e 中大量断言绑旧 DOM（三屏结构/双栏选择器）——整壳重构后逐条适配；策略：桌面(1280)/平板(900)/移动(375) 三档视口全跑，桌面为默认（本阶段起桌面是第一公民）
- **新增**：对话工作台（跨条目共享流/刷新恢复/50 轮上限/报告收录断言）、抽屉开合、粘贴文本审查、左栏历史记录回跳、跨合同对话隔离（沿用十轮教训：退出上下文统一清理）
- 回归纪律：每批合并附冻结哈希全量回归（B7-5 阶段基线 1533 passed）

## 五、费用纪律

- 对话工作台/改版施工全程零 LLM（纯存储+UI）
- 试用走预览服务，费用走既有线上闸（老板知情：该花就花）
- 粘贴文本审查与 B7-6c 补写：每单/每条新增 LLM 调用面——上线前在费用表登记（B7-4 教训：首传费用必须先对账口径）
