# Claude Code 交接：本机具名规则审核进展

日期：2026-11-09。用户目标仍是完成规则管理及用户管理；用户允许管理员审核自己提交的规则，暂不部署。先前基线见 `handoff-20261109-goal-before.md`，保留现有工作区和 `trial-db/`。

## 已实现的本机试验链路

- 管理员将已开放品类的当前文件导入隔离账户库作为试用基线。普通用户或管理员按固定内容摘要和 generation 提交新候选；服务器根据受限字段构造规则并保存真实操作者、结构化差异、理由和实际正反例结果。相同账户/请求编号重试幂等；冲突或基线变化拒绝。
- 本机候选可以运行仓库对应品类金标。候选规则放临时配置目录，由单独 Python 子进程运行，结果记录完整候选摘要、测试输入摘要、测试计数与范围；不传模型密钥。跳过、超时、运行时输入变化或失败不能作为通过。该机制仍依赖当前本机 Python/依赖，**不是文件系统或网络沙箱、不可变构建，也不是完整回归**。
- 独立审核发现 `pytest.ini` 等配置可能改变测试收集但未计入金标摘要；已将常见根目录测试配置和依赖清单纳入金标及完整回归原型摘要，并增加定向测试。摘要仍未冻结所有执行环境和依赖内容，不能替代不可变构建。
- 新审查建档时保存本地规则文件的完整 SHA-256，网页显示短摘要、报告显示完整摘要；旧记录标记未知。该摘要只标识所选文件，不能证明规则成功执行、引擎版本或完整环境，亦不能凭摘要恢复文件。失败记录保留已选定摘要。
- 新审查保存立场标签、声明和知情提示；网页、报告、质量层及追问使用所捕获或保存的标签。旧记录没有历史字段时，会明确标记按当前配置重建或未知。追问模型链路已用模拟供应商验证，尚未用真实模型验收。
- `RuleVersionStore.capture_current` 用单次数据库查询绑定原始规则字节、完整摘要、版本 ID 与代次；当前没有接入实际合同审查，也不提供授权或发布能力。已补充读写并发测试；未来接入时须同时传递来源、版本和代次，不得把数据库版本标成本地文件。
- 测试任务有 SQLite 持久化 running/completed/failed/abandoned 状态和单任务约束；新测试运行时不能用旧测试审批，失效租约由下一次验证时处理。具名管理员审核绑定页面实际看到的 validation ID、候选摘要和当前 generation；管理员可自审并标示。测试环境变化会使旧结果显示过期且拒绝新审核。测试后再测试需重新审核。
- 新增本机账户绑定的 `/api/local-accounts/rules` 接口和规则审核试用页面：初始化基线、提交新候选、看结构化差异与示例、运行金标、审核/退回。只允许直接环回访问；普通用户只看本人候选，管理员能查看审核所需信息。示例在账户库明文保存，提交前界面要求确认；不自动读取合同原文。名称为账户当前显示名，附账号和短 ID，不代表实名认证。
- 候选目录按经授权的 UUID 游标分页，避免并发新增时重复/漏读及泄露全局序号；新增项检查归一化同名和可还原纯字面的精确关键词冲突。复杂正则和语义相近冲突仍需人工检查，不能称为全面冲突检测。
- 草稿界面与候选规则现一致限制普通流程编辑或停用包含硬性规则的项目。现有未认证草稿库并没有归属或版本化提交，新增界面提交的是新候选，不能称为直接提交既有草稿。

## 仍未完成，禁止当成正式上线

1. 当前基线、候选与审核不会改变合同审查使用的文件规则；未实现真实发布、原子生效、回滚及历史/在途版本一致性。新增 `rule_release.py` 只是内部事务原型：以合成完整回归记录测试了权限、代次、并发及回滚事件；没有真实完整回归记录生成器或发布 API，也没有连接合同引擎。独立审核发现环境摘要漏掉测试配置：已补入 `pytest.ini` 等文件，但尚未冻结所有真实输入；摘要计算与切换之间仍存在文件变化窗口，回滚未验证旧版本与当前环境兼容。须先引入受控不可变构建、真实回归和经验证的回滚策略，禁止开放原型。
2. 金标只是固定品类测试，未覆盖完整工程回归、全部评分依赖、法律适用和预期变化审批；现有部分 NDA/采购金标已改用稳定 ID 或候选模式兼容新增项，但不能把有意改变的金标结果自动放行。正式门禁须采用受控、不可变构建和完整测试/数据集证据，定义有意变化的法务确认。
3. 现有 `ReviewStore` 无个人归属，合同及其报告、对话、异议、提案和修订接口尚无逐对象账户隔离。当前账户 cookie 仅限账户接口，本机 HTTP 和跨端口也不具备生产隔离。旧账户/候选库缺新字段时明确拒绝，尚无通用迁移和恢复方案。
   独立盘点还确认列表和异议提案聚合会跨合同返回信息，且账户与合同在两个数据库：单独在路由检查后再写入不能保证撤权并发安全。AI 长操作须在发送前、提交结果和响应前重新授权，不能继续使用删除/撤权后的旧快照。旧无主记录需隔离并明确认领方式，不能静默分配。
4. 审查引擎、品类目录、预审提示和历史报告仍有直接读取当前 YAML 的路径，运行结果只有短内容摘要；需统一从可信版本捕获并保存完整版本/构建身份。`ReviewStore` 进程启动会把所有 processing 单据标为失败，多进程部署前必须解决任务归属与恢复，不能假设现有逻辑安全。
5. 审核详情中展示的示例为用户提交的明文，本机试验已提示，但生产仍需确定授权、脱敏、期限与删除策略；不可复制个人合同原文进入长期规则库。独立审核仍须继续覆盖权限、依赖与并发。
