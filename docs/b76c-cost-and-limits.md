# B7-6c 补写调用预算与验收记录

日期：2026-11-07。此文为开发期预算说明，不是供应商实际账单，也不代表已批准发布。

- 单份审查最多预留 4 次补写尝试、36 次模型调用。每次先按最坏路径一次性预留；普通失败和提前命中不退回预留额度。进程中断经锁确认后，尚未发出的预留会释放；已开始的调用按可能计费保守保留。没有密钥、正文为空、超过长度上限、负清单或保护领域拦截时不调用模型。
- 最长处理 200,000 字正文；不超过 6,000 字时最多 1 次模型调用；超出时按每段最多 6,000 字、相邻重叠 200 字逐段检查，必要时再调用 1 次生成参考。20 万字最坏预留 36 次。命中可提前结束，实际计费调用数可能少于预留数。
- 每次真实供应商调用走既有调用账本；额度拒绝记录 budget_exceeded。调用金额取决于实际供应商、模型、输入输出 token 及计价，未估算成固定人民币数额。试用或上线前应根据调用账本和供应商账单核对，包括首次请求。
- 安全边界：所有分段完成仍不等于证明合同缺失，模型可能漏检；引用只验证文字是否出现在原文，不能自动证明法律含义。生成内容仍需人工核对。高风险词与数值检查是保守启发式，不能保证识别全部特殊事项或非中性表述。
- 中断恢复：每个任务使用同机跨进程文件锁；确认锁已释放后，第一次重试仅提示中断和可能已计费，不自动重发，用户再次点击才重新检查。旧版未带锁记录无法安全判断是否仍在运行，需重新提交合同。若剩余调用额度不足以重新检查，也需重新审查合同。SQLite WAL 与锁文件要求数据库位于同机本地文件系统；跨主机共享网络文件系统不受支持。长合同可能跨越网关等待时限，发布前仍须验证实际部署链路。
- 验证：自造短合同中“已写在别处”和“未发现”；自造长合同中“中段有约定”和“所有分段未发现”已用真实模型冒烟。样本量小，不代表真实合同的召回率、误报率或安全合规率。

补充：调用账本按既有设计为失败不阻断业务的记录机制；若账本写入异常，不能仅凭账本断言所有调用都已入账，仍须结合供应商账单核对。

兼容补充：数据库迁移会为旧版任务保留“无法确认”的标记；如果旧进程在迁移后使用旧方式重新开始任务，数据库触发器也会将其标为旧版，避免新版误判为可安全恢复。旧记录不会被自动重发。

补写节点的单次输出上限登记为 6000 tokens（不是调用次数）；超过上限可能导致结果截断并提示重试。一次自造合同真实接口冒烟账本记录输出 632 tokens、费用字段为空；这只能说明该次未触顶，实际费用仍以供应商账单为准。

原文定位：查证提示命中后，用户可读取该摘句附近的有限上下文，服务器在返回前重新核验位置并对原文截断；同一摘句出现多处或已无法定位时只提示人工核对，不猜测位置。这是只读操作，不产生模型调用费用。旧版服务不提供该按钮。
