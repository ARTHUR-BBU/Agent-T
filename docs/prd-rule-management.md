# 规则管理 PRD

> 2026-11-10 状态更新：下文 11 月 9 日以前的“尚未实现”保留为阶段记录。现已有本机账户、具名候选审核、品类金标和版本事务原型；规则编辑及启停仍需经候选流程，尚未正式生效。实际合同审查仍读取本地规则文件，正式发布、经验证回滚、合同账户隔离和生产迁移均未完成。最新实现、测试及限制见 `handoff-20261109-rule-review-after.md`。

状态：开发中；2026-11-09。目标用户是规则维护人、法务审核人和发布负责人。目标是让规则可查看、可安全变更，并让每次审查的依据可追溯。AI 建议仅为素材，不代表审批。

## 现状与范围

现有规则位于品类 YAML 和程序匹配器；单据中的异议提案随审查记录过期，审核人姓名未认证，采纳并不改变正式规则。当前无独立个人身份、正式版本发布或客户隔离。第一步提供当前清单只读目录；其后的草稿、验证、审批与发布须逐阶段实现。系统规则与客户定制规则的优先级、租户边界和证据保存期限尚待明确，不将单工作区说成多租户。

本机开发进度（2026-11-09）：已有明确开关的环回直连草稿试用，支持新增字面关键词检查项、修改名称/说明、建议停用、查看差异、修改和删除草稿。现有引擎没有真正的单项停用能力，因此目前不存在可提交启用建议的已停用项。新增草稿通过现有规则引擎检查一组虚构正反例；这不是完整规则验收。草稿明文保存在单独 SQLite，删除不保证备份或存储介质残留被清除。严禁在未设计真实身份和权限前经反向代理或公网开放此试用功能；代理可能隐藏真实请求来源。人工审批、规则正式生效、规则版本库、全面测试和发布回滚仍未实现。

## 能力地图及体验

1. **catalog**：按品类查看当前检查项、分类、说明、配置中允许展示的字段及配置内标注的版本；程序匹配器需结合代码理解。未标注版本则如实说明，配置版本号不是完整执行版本或内容指纹。明确它是当前文件配置，不代表每个历史审查的快照，也不假称拥有单项启停开关。不存在规则时显示空态，读取失败显示错误，可关闭后重试。详细规则面向可信试用环境，客户私有规则接入前须建设身份及授权；不把未知配置字段自动暴露。
2. **draft**：以固定基线创建新增、修改、停用草稿；输入适用范围、理由和正反例，逐项对比新旧内容。复杂匹配器先只读并交开发人员维护，不接收任意 Python 或正则；核心硬性规则不得由普通草稿直接删除或降级。保存草稿不影响正式审查。
3. **validation**：完整结构、matcher、表达式、重复 ID、分段权重与依赖校验；逐规则正例、反例和边界，历史合同回放与现有全量回归，标出预期变化和意外变化。缺少样例、未通过或版本过期不得进入发布。
4. **review**：规则维护者提交固定候选版本，法务/专业审核者查看差异、样例与测试结果并记录理由。变更后旧审批和测试失效。必须以真实个人身份和权限实施；共享密码或手填姓名不构成身份认证。
5. **release**：授权发布者在审批与测试均匹配同一版本时发布；原子切换、留存审计、支持回滚。一次审查冻结规则、评分和证据版本，执行和记录同源；旧审查不被重算，回滚仅影响后续新审查。
6. **proposal intake**：将现有异议作为草稿的可选来源；仅在确定授权、脱敏、保存期限及删除策略后接入，不静默复制合同原文或绕过原记录过期策略。

## 核心数据和状态

规则包版本：品类、内容摘要、来源、创建时间、发布状态；条目及规则具有稳定身份，旧有按序号生成的 `#r`/`#p` 标识须有版本内映射。变更申请含基线版本、差异、范围、理由、样例、操作者；校验结果绑定候选内容摘要；审批含身份、决定、理由与时间；发布事件含前后版本、执行者和回滚来源。状态为草稿 → 待验证 → 待审批 → 可发布 → 已发布 / 已撤回，任何内容变更回退为草稿；并发修改需基线检查，冲突不得覆盖。

## 验收与限制

- 查看目录时，所展示字段与实际已开放品类配置一致；错误和空结果明确，不提供虚假的编辑或启停按钮。
- 一条定制规则需有适用及不适用示例，测试通过并由具名授权人审批后方可发布；失败、过期审批或过期基线均不可发布。
- 长审查跨发布时仍使用同一套规则、评分与版本；历史结果不变；版本可追溯、回滚可审计。
- 停用前检查评分、报告、AI 发现及补写依赖；优先版本化停用而非删除。客户数据及合同证据的访问、留存和清除在接入前确定。
- 本文为需求，除已明确标注的首批只读功能外，均不表示已实现或可上线。法律文案与样例需专业人员确认。
