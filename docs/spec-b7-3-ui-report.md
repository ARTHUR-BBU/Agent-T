## 一、目标

让用户在网页上真正用起「改得有用」全链，并把成果带进报告：

1. **页面三卡**（检查项详情内，逐项懒加载，不在审查主路径）：
   - **改写建议卡**：对「需关注」且有原文的项，点按 → 三版草案
     （稳妥/平衡/进取）+ 每版适用说明 + 三版共同理由 + **显式事实假设**
     + 非法律意见声明
   - **选定卡**：三版中选定一版（必须落到版别：稳妥/平衡/进取），
     选定≠生成≠重审三分
   - **牵连检查卡**：选定后可发起 → 其他关联条款摘录+逐条一致性说明
     （findings）；查不到关联条款如实标「未覆盖（不代表没有冲突）」；
     报告尾部固定**重审提示**（选定草案≠解决问题）
2. **报告草案章节**（docx）：导出报告新增「修改建议」章节——已选定
   草案 + 原文对照 + 假设 + 牵连 findings（如有）+ 声明与重审提示

## 四、依赖与接口（全部已上线，零后端新调用面）

- `POST /api/review/{rid}/items/{iid}/revision` → 三版草案（含 draft_id、
  assumptions、declaration）
- `POST .../revision/select`（body: draft_id + **stance**）
- `POST .../revision/impact`（body: draft_id）→ ok（findings/excerpts/
  notice）/ uncovered（不代表没有冲突）/ degraded / budget_exceeded
- 交互预算闸已在后端（revision 4/卷、impact 3/卷，持久累计）——前端
  只需如实展示预算耗尽态，不得自行重试
- 报告层：`GET /api/review/{rid}/report`（docx）；草案数据读
  `revision_drafts`（选定态）+ `selected_drafts`

## 四A、状态恢复设计（v2 新增，codex #161 复批 P1）

**问题**：现有三个 POST 接口只管触发，页面刷新后三卡状态无从恢复；
绝不能让前端靠「重新调 AI」恢复（重复花钱）。

**方案：新增三个只读 GET 接口（纯读库，零 LLM 调用，本次唯一后端增量）**：

| 接口 | 返回 | 用途 |
|---|---|---|
| `GET .../revision` | 该项最新草案（draft_id/三版/assumptions/declaration/status）+ 历史draft_id 列表 | 改写卡刷新恢复 |
| `GET .../revision/selection` | 当前选定 (draft_id, stance) 或 null | 选定卡刷新恢复 |
| `GET .../revision/impact-report` | 当前选定版对应的最新 impact 报告（ok 含 findings/uncovered/degraded 原因/从未发起=null） | 牵连卡刷新恢复 |

- 前端刷新时**只调 GET**，按返回态渲染三卡；触发新调用必须用户显式点按
- 报告导出（B7-3b）同样走读取：`selected_drafts` + 该选定版对应的
  最新 ok impact 报告——**报告层不自行调 AI**

**选定一致性（牵连检查必须对应当前选中版）**：impact 报告落库时绑定
(draft_id, stance)；选定变更后，旧选定版的 impact 报告对**当前选定**
而言标记「对应此前选定版本，已过期」——页面与报告只展示**当前选定版**
的检查结果；未检查/未覆盖/降级三态如实展示（见 §六），不互相顶替。

## 五、红线（延续 M7 四红线 + 新增报告层两条）

1. 非法律意见声明 + 禁语过滤**在报告层复用**（docx 草案章节引用草案
   文本前过同一禁语表，B7-0 先修禁令的延伸）
2. 只对已打标检查项提供改写，禁进攻性条款
3. 三层留痕+假设层完整呈现（原文/修改文本/理由/假设）
4. 建议不回写判定层
5. **新增**：报告草案章节必须带重审提示（选定草案≠解决问题）
6. **新增**：未选定草案时报告章节如实显示「未选定修改建议」（不虚构）

## 五A、报告层模型内容展示/过滤/降级规则（v2 新增，codex #161 复批 P1）

「禁语表判安全」只是最后一道；每类内容的完整处理：

| 内容 | 来源 | 过滤 | 降级/如实展示 |
|---|---|---|---|
| 原文对照 | item.quote（规则层既有，未经模型） | 不过滤（规则层产物） | 无 quote 的项不进草案章节 |
| 草案文本 | 选定版 versions[stance].text | **禁语表复用**（引用前过表，命中=该版整体不入报告，如实标「未入选」） | 未选定=章节显示「未选定修改建议」 |
| 理由/假设 | 草案 payload rationale/assumptions | 同上（随所属版整体处置） | assumptions 空=标「无补充假设」 |
| 牵连 findings | impact_reports（当前选定版最新 ok） | 不再过滤（已是模型产出经 Schema 校验的定位说明）+ 章节头声明「AI 一致性定位，不构成法律意见」 | 未检查=「尚未发起」；uncovered=如实「未覆盖（不代表没有冲突）」；degraded=「分析失败已留痕」 |
| 重审提示 | 固定常量 | — | 任何形态都必带 |

- **报告数据一致性**：章节内容与选定版绑定（draft_id+stance）；换选后
  旧版 findings 不出现在新版草案下（见 §四A）
- **法务逐例语义核对仍属验收**：B7-3b 报告章节完成后，抽真实样例导出
  报告交老钱核对展示与过滤的正确性（零新增付费，复用 B7-2 已有产出）
- 所有展示态文案（降级/预算耗尽/未覆盖）经九哥评审，禁技术黑话
