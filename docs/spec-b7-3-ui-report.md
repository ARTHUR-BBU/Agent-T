## 一、目标

让用户在网页上真正用起「改得有用」全链，并把成果带进报告：

1. **页面三卡**（检查项详情内，逐项懒加载，不在审查主路径）：
   - **改写建议卡**：对「需关注」且有原文的项，点按 → 三版草案
     （稳妥/平衡/进取）+ 每版适用说明 + 三版共同理由 + **显式事实假设**
     + 非法律意见声明
   - **选定卡**：三版中选定一版（必须落到版别：稳妥/平衡/进取），
     选定≠生成≠重审三分
   - **牵连检查卡**：选定后可发起 → 其他关联条款摘录+逐条一致性说明
     （findings）；查不到关联条款如实标「未覆盖（不代表没有冲突）」；
     报告尾部固定**重审提示**（选定草案≠解决问题）
2. **报告草案章节**（docx）：导出报告新增「修改建议」章节——已选定
   草案 + 原文对照 + 假设 + 牵连 findings（如有）+ 声明与重审提示

## 三、非目标（明确不做）

- 逐节点熔断（主审查链不改动，既有挂账另立项）
- 禁语表「语义而非字面」扩样（B7-2 挂账，挂禁语表修订批）
- 牵连摘录窗口去重（B7-2 挂账 P3，随本批顺带评估，不承诺）
- 报告层回写判定层（红线：建议永不改判定）
- 五题考试未覆盖的话术变体防护（挂账）

## 四、依赖与接口（全部已上线，零后端新调用面）

- `POST /api/review/{rid}/items/{iid}/revision` → 三版草案（含 draft_id、
  assumptions、declaration）
- `POST .../revision/select`（body: draft_id + **stance**）
- `POST .../revision/impact`（body: draft_id）→ ok（findings/excerpts/
  notice）/ uncovered（不代表没有冲突）/ degraded / budget_exceeded
- 交互预算闸已在后端（revision 4/卷、impact 3/卷，持久累计）——前端
  只需如实展示预算耗尽态，不得自行重试
- 报告层：`GET /api/review/{rid}/report`（docx）；草案数据读
  `revision_drafts`（选定态）+ `selected_drafts`

## 五、红线（延续 M7 四红线 + 新增报告层两条）

1. 非法律意见声明 + 禁语过滤**在报告层复用**（docx 草案章节引用草案
   文本前过同一禁语表，B7-0 先修禁令的延伸）
2. 只对已打标检查项提供改写，禁进攻性条款
3. 三层留痕+假设层完整呈现（原文/修改文本/理由/假设）
4. 建议不回写判定层
5. **新增**：报告草案章节必须带重审提示（选定草案≠解决问题）
6. **新增**：未选定草案时报告章节如实显示「未选定修改建议」（不虚构）

## 六、验收方案（送审时细化）

- **B7-3a（UI）**：手工验收清单（生成→选定→牵连→预算耗尽态展示→
  降级态展示→未覆盖态展示）+ E2E 脚本（mock）；阳仔线框符合性
- **B7-3b（docx）**：确定性契约测试（同输入同字节，M4 红线）+
  禁语过滤报告层回归（含委婉变体考卷回放：报告层引用带禁语草稿必须
  拦截）+ 无选定/有选定两形态快照
- 全量回归 + CI 双绿 + codex 复批 + 老钱抽查报告章节法务表述

## 七、费用口径

## 八、风险

- 前端展示降级/预算态的文案需九哥评审（面向用户话术，禁技术黑话）
- docx 章节使报告体积增长（预估 +10~20%，确定性契约测试锁定格式）
- 多端（移动端）布局适配——阳仔评审范围
