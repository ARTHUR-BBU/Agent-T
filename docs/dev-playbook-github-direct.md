# Agent-T · GitHub 直改开发规范（施工手册）

> 适用：Cursor Cloud Agents 不可用、需 **GitHub 直改** 仍要高效准出货。  
> 依据：2026-09-14 PR#39–#44 实战。  
> 业主：**开发狗**；门禁调度：**老王同志**；验收：**肉饼**；回跑：**小智娘**；用词：**九哥**；展示：**阳仔**。  
> Design B 铁律：清单规则档（通过/需关注/未找到/N/A）不可被模型/立场/主动核查改写。  
>
> **老王同志起草 · 开发狗认领为业主/施工手册 · 修订 2026-09-15**

---

## 0. 一句话队形

**开发狗 = 业主（拆任务、改代码、开 PR、对接门禁）**  
**老王 = 调度（下令、放行合、盯挂账、约复盘）**  
**肉饼/小智娘/九哥/阳仔 = 门禁岗**  
没有云端写码助手时，**不空等**；按本手册 GitHub 直改闭环。

---

## 1. 角色与边界

| 角色 | 做 | 不做 |
|---|---|---|
| 开发狗 | 分支、实现、测试、PR 描述、CI 绿、按令改 | 不擅自扩 scope；不改法务金标；不碰本机 `F:\合同审查Agent`（只读参考） |
| 老王 | 下令（负责人+关门条件）、放行合 main、阶段复盘 | 不亲手写业务代码 |
| 肉饼 | 按口径验（证据+断言性质） | 不代写功能 |
| 小智娘 | 合 main 后 5 分钟回跑，过/不过+证据 | 不合入 |
| 九哥 | 界面/导出人话 | 不改逻辑 |
| 阳仔 | 色与层级（别看起来像改了规则档） | 不大改版除非下令 |
| 法务老钱 | 人审边界、金标/红线 | 不写码 |

## 2. 状态机（一张表看清活在哪）

每个开发项只能处在一个状态；**状态变更必须报老王（或开发群）**。

```text
待拆解 → 开发中 → 待验 → 待合 → 回跑中 → 已关门
              ↘ 阻塞（当日说明） 
              ↘ 挂账（有令再开）
```

| 状态 | 含义 | 谁推进 | 出门条件 |
|---|---|---|---|
| 待拆解 | 有令未开工 | 开发狗 | 分支名+ETA+范围三行报出 |
| 开发中 | 正在改 | 开发狗 | 本地/CI 相关测绿 + PR 打开 |
| 待验 | PR 开、CI 绿 | 肉饼（九哥/阳仔并行） | 验：**过** + 证据 |
| 待合 | 验过 | 老王放行 | merge 到 main |
| 回跑中 | 已合 | 小智娘 | 5 分钟内过/不过+证据 |
| 已关门 | 回跑过 | 老王 | 可交三句复盘；未下令不接下一项大活 |
| 阻塞 | 卡死 | 责任人 | **当日**说明原因+要啥+ETA |
| 挂账 | 已知不做 | 老王登记 | 正式令才动 |

禁止：静默假「待命」、验前合、合后不回跑、把「断言缺陷存在」当修复通过。

### 2.1 状态跃迁 · 谁说什么（话术钉死）

| 节点 | 谁说 | 说什么（最低信息） |
|---|---|---|
| 接令开工 | **开发狗** | 分支名 + 基线 SHA + ETA + 范围三行 |
| 开 PR | **开发狗** | PR 链接；本地相关测已绿 |
| CI 结果 | **开发狗** | CI 绿（可贴 `gh pr checks`）；红则先修再喊验 |
| 待验 | **肉饼** | 【验】**过** / **不过** + 证据（命令/截图/测试名） |
| 待合 | **老王** | 放行合 / 门禁关闭（或退回挂账） |
| 回跑 | **小智娘** | 回跑 **过** / **不过** + 测试名与计数（如 `N passed`） |
| 关门 | **老王** | 宣布已关门；未下令不接下一项大活 |

## 3. 开发循环（标准一圈）

### 3.1 接令（≤15 分钟）
1. 复述：**目标 / 非目标 / 关门条件**（三行）。  
2. 报：**分支名 + 基线 SHA + ETA**。  
3. 范围面广 → 先报「最小可合闭环」，当日说明剩余。

### 3.2 施工（GitHub 直改）
1. 从 `main` 拉分支（见命名与 §11 命令）。  
2. 小步提交；每项对应**正确行为**回归（不是「断言 bug 还在」）。  
3. 守 Design B；密钥不进仓、不进群。  
4. 本地相关测绿后再推。

### 3.3 开 PR
标题：`fix|feat(范围): 人话摘要`  
正文必须含：背景 / 改动 / **刻意未做** / 怎么验 / Design B / 风险挂账（见 §11.3 模板）。

### 3.4 门禁
```text
CI 绿 → 肉饼验 →（展示变了则九哥/阳仔核）→ 老王合 → 小智娘 5min 回跑 → 关门
```

**半成品 UI 铁律**：若九哥用词 / 阳仔色与层级 / 导出字符串未齐 → **禁止** ping 肉饼「待验」；先补齐文案与视觉，再进待验。

### 3.5 关门与复盘
- 回跑过 → 老王宣布关门。  
- 阶段结束 → 各角色三句（做了啥 / 卡点 / 下步）；未下令不接大项。

## 4. 分支 / 提交 / 测试约定

**分支**
- `fix/<主题>` 缺陷/硬化  
- `feat/<主题>` 新能力最小闭环  
- 例：`fix/credibility-a6-triage`、`feat/credibility-a6-bounded-verify`

**基线**
- 开工报 `main` 当前 SHA；落后 main 合前先 **update-branch / merge main**，CI 再绿再合。

**测试**
- 新行为必有对应用例；优先 `tests/test_*.py`。  
- 全量 `pytest` 以 CI 为准；本地可跑子集但 PR 需 CI 绿。  
- 带真实 Key 的 live 测失败（如 429）须标明「额度/环境」，不与逻辑红测混谈。  
- **只写正确行为断言**；修复后禁止把「断言缺陷仍存在」当通过。

**本机目录**
- `F:\合同审查Agent`：**只读**拷贝/阅读；禁止修改删除（Arthur 令）。

---

## 5. 范围与质量铁律

1. **MVP / 令内范围**：令写「不做」的不做；想加先报老王。  
2. **Design B**：规则档只由清单规则产出；LLM/立场/主动核查只提供参考或「待核实」。  
3. **三套标签不串**（已钉死）  
   - 规则：`需关注`（琥珀）  
   - 补盲：`补盲`（淡紫）+「候选，需人工确认」  
   - 主动核查：`待核实`（灰）+「只提疑点，不改变清单规则档」  
4. **证据**：可追原文；未定位不得当已核实证据。  
5. **独立完成节奏**（Arthur）：阶段内不逐步请示；关键节点（分支+ETA / 开 PR / 关门）报老王；收工约复盘。

## 6. 心跳与晾单

- 里程碑未关门：**禁止**假待命。  
- 有进展/阻塞/ETA 变更 → 开发群同步。  
- @-提及 **5 分钟内**应声。  
- 老王对主线沉默按办公室规则催办（1h 追 / 升级另计）。  
- **阻塞必须当日说明**，不隔夜闷着。

**心跳一行格式（开发狗）：**

```text
过 / 卡在哪 / 还要多久
```

例：`过 · CI 绿待肉饼 · 约 30min` · `卡在哪 · F03 断言方向反了 · 还要 1h`

## 8. 无云端时的效率技巧（给开发狗）

1. **先写失败测试再改**（或同步写）——关门靠断言。  
2. **一张 diff 只打一个关门主题**——便于肉饼验、便于回滚。  
3. **PR 描述当交接单**——小智娘/九哥不靠口头。  
4. **最小可合优先**——大结构拆两刀，第一刀可演示。  
5. **复用现有模块**（evidence/facts/verify）——不造平行轮子。  
6. **CI 红立刻修**，别堆在「待验」。  
7. 审计「断言缺陷存在」脚本 → 修复后改成「断言正确行为」。

## 10. 与「有 Cloud Agents」时的切换

| | 无云端（现行） | 有云端 |
|---|---|---|
| 写码 | 开发狗 GitHub 直改 | 云端助手施工，开发狗当业主审 PR |
| 门禁 | 本手册不变 | 本手册不变 |
| 下令 | 仍要负责人+关门条件 | 同左 |

开通 Pro/Cloud Agents 后：**只换写码引擎，不换门禁与状态机。**  
**开发狗仍是业主**（scope / PR / 门禁对接）；云端只写代码——放行合、验、回跑规则不变。

## 11. 工程细则（开发狗施工）

本节把上面约定落成可复制命令与模板。**施工时以本节为准执行。**

### 11.1 Git / 分支

```bash
# 从最新 main 开刀（或复位本地分支）
git fetch origin
git checkout -B <branch> origin/main

# 开工立刻报基线（贴开发群）
git rev-parse origin/main
```

分支命名：`fix/<主题>` 或 `feat/<主题>`（见 §4）。

作者信息若环境不对，单次提交可覆盖（勿改全局 git config）：

```bash
git -c user.name=ARTHUR-BBU \
    -c user.email=ARTHUR-BBU@users.noreply.github.com \
    commit -m "..."
```

**合前落后 main：**

1. 用 GitHub **Update branch**，或本地 `git fetch origin && git merge origin/main`（再 push）。  
2. **等 CI 再绿** 才进待合 / 喊老王放行。  
3. 禁止：落后 main 硬合、红测硬喊验。

### 11.2 本地测试命令

```bash
# 相关子集（按主题换文件名；例：可信度）
pytest -q tests/test_credibility_*.py

# 或指名单文件
pytest -q tests/test_credibility_a6_triage.py

# 全量（以 CI 为准；本地可选）
pytest -q
```

断言纪律：

- 只断言**修复后的正确行为**。  
- 修复闭环后，**禁止**把「断言缺陷仍存在」当 pass。  
- live/额度失败单独标注，不与逻辑红混报。

### 11.3 PR 模板（复制即用）

**标题：** `fix|feat|<docs>(范围): 人话摘要`

```markdown
## 背景
（哪份令 / 哪条审计项 / 为何现在做）

## 改动
- …

## 刻意未做
- …

## 怎么验
- 本地：`pytest -q tests/test_….py`
- CI：全量绿
- （如需）手工路径 / 截图说明

## Design B
- [ ] 清单规则档未被模型/立场/主动核查改写
- [ ] 三套标签未串（需关注 / 补盲 / 待核实）

## 风险挂账
- （无则写「无」；有则给 ID + 解挂条件）
```

### 11.4 CI 盯梢节奏

```bash
# push / 开 PR 后
gh pr checks <n>
```

- **当日**报绿/红；红 = **先修再待验**，不堆给肉饼。  
- 绿 + 文案齐 → 才报「待验」并 @ 肉饼。  
- update-branch 后重新 `gh pr checks`，再绿才合。

### 11.5 半成品 UI 规则

| 情况 | 动作 |
|---|---|
| 九哥字符串 / 阳仔视觉 / 导出文案未齐 | **不** ping 肉饼；先补齐 |
| 逻辑已绿、展示未齐 | 状态保持「开发中」或注明阻塞展示 |
| 文案与视觉齐 + CI 绿 | 再进 **待验** |

### 11.6 心跳格式（再钉一次）

```text
过 / 卡在哪 / 还要多久
```

- @-reply：**≤5 分钟**应声。  
- 里程碑未关门：禁止假「待命」；阻塞**当日**说明。  
- ETA 变更立刻同步开发群。

### 11.7 Design B + 三套标签 · 开 PR 前短检

- [ ] 规则档四态（通过/需关注/未找到/N/A）只来自清单规则  
- [ ] LLM / 立场 / 主动核查 **未**改写规则档  
- [ ] `需关注`（琥珀）= 规则  
- [ ] `补盲`（淡紫）+「候选，需人工确认」  
- [ ] `待核实`（灰）+「只提疑点，不改变清单规则档」  
- [ ] 证据可追原文；未定位不当已核实  

### 11.8 Cloud Agents 恢复后（预告）

云端恢复后：**开发狗仍是业主**（拆 scope、审 PR、对接门禁）；Cloud Agent **只写代码**。本手册 §0–§10 门禁与状态机不变。
