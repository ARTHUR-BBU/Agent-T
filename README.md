## 合同读完了，心里还是没底？

钱什么时候付，押金什么时候退，出了问题谁负责——真正影响你的，往往藏在这些具体约定里。

Agent-T 帮你做签约前的第一轮梳理：上传合同，查看需要留意的地方，对照原文，再继续问“这会怎样影响我？”“可以怎么改？”

**让第一次沟通，就能问到关键处。** 无论你是准备签约的业务负责人、核对付款条件的财务，还是希望先整理问题的法务与审计人员，都可以从这里开始。

## 从一份合同，到一组可以讨论的问题

| 你想弄清楚的事 | Agent-T 如何帮你 |
|---|---|
| **先看哪里？** | 按合同类型核查常见事项，列出“需关注”和“未找到”的约定，方便逐项查看。 |
| **为什么值得留意？** | 展示核查说明、原文摘句与条款位置，把问题放回合同语境里理解。 |
| **还有什么值得再看一眼？** | 接入 AI 后，补充完整性、条款一致性和实际影响方面的参考观察，供人工核实。 |
| **还有什么需要我确认？** | 对证据没有闭合、需要商业判断或可能另有附件的问题继续取证，把真正需要你决定的事项集中列出来。 |
| **应该怎么问、怎么谈？** | 对系统标记“需关注”的条款继续追问，获取解释、修改建议和建议改写稿。 |
| **怎么交给同事一起看？** | 导出 Word 报告，汇总逐条核查、参考评分与候选风险；也可以用手机查看结果。 |

AI 功能需要配置模型服务。当前 Word 报告不包含页面中的 AI 观察与追问回答，转交前请留意报告范围。

## 不只标出问题，还会继续核查

很多合同工具像一道安检门：碰到关键词就报警。Agent-T 希望更进一步，像一位谨慎的审核助理——**发现疑点后，先回到合同里寻找证据，再决定该提醒你什么。**

> **先提出怀疑，再寻找证据；有证据才判断，没有证据就说明还缺什么。**

当前 MVP 已经具备第一版有界主动核查闭环：

**疑点 → 按条款取证 → 核对摘句与事实 → 请你确认 → 再审本条**

- 能在合同原文中核对摘句和所在条款，避免拿一句不存在的话支持结论。
- 能把证据完整、无需价值判断的事实留给系统处理，把证据断裂、金额不一致、附件可能缺失等事项交给人确认。
- 你可以补充情况、确认或提出异议，再让系统重新核对这一条。
- 每轮核查都有次数和取证上限；主动核查只提出疑点，不会悄悄改写原来的规则结论。

它的价值不在于多显示一个“风险”标签，而在于把一个模糊提醒变成三个可以继续处理的问题：**依据在哪里、实际会怎样、下一步做什么。**

### 一个现实场景：付款前，到底算不算验收合格？

一份采购合同写着：

> 货物交付后，采购方应支付 95% 的合同款。

只看这一句，系统可能提醒“付款比例较高”。但真正决定风险的，往往是散落在其他位置的约定：

- 验收条款写着“到货后三日内未提出异议，视为验收合格”；
- 技术附件却写着设备需要安装、调试七日后才能判断性能；
- 付款条款又把“验收合格”作为付款条件。

主动核查要继续追问：**交付是否等于验收？三日从什么时候开始？设备尚未调试完成，为什么已经可能被视为合格？**

如果这些证据能够相互对应，使用者需要看到的就不该只是一句“请注意付款风险”，而是：

> 验收期限短于实际调试周期。采购方可能在尚未确认设备性能前，就被视为验收合格并触发 95% 的付款义务。建议将验收期限改为“安装调试完成后七个工作日”，并明确只有书面验收合格才触发付款。

同时列出可回到原文核对的位置：付款条款、默认验收条款和技术附件。这样，业务、财务和法务讨论的是同一组事实。

<details>
<summary><strong>再看两个现实场景：押金和背靠背付款</strong></summary>

**租赁押金**

合同写着“出租方确认房屋无损坏、无欠费后，于 60 日内退还押金”。真正需要核查的是：谁来确认、正常损耗是否算损坏、出租方迟迟不确认时 60 日是否永远不开始计算、有没有交接清单和异议期限。

如果这些约定都缺失，问题就不只是“退款较慢”，而是退款条件完全由出租方控制。更可执行的建议是：双方退租时签署交接清单，出租方应在五个工作日内提出书面异议，逾期视为交接完成，并在十个工作日内退还无争议的剩余押金。

**背靠背付款**

分包合同写着“甲方收到最终客户支付的项目款后，再向乙方付款”。主动核查首先要确认双方企业规模、合同类型、签订时间和适用规则，再继续寻找：最终客户长期不付款怎么办、未付款是否由甲方造成、乙方已经履约时有没有最长等待期限、甲方是否需要提供未付款证明。

这一步不能只做文字优化。在中国大陆，大型企业在建设工程施工、采购货物或服务中，与中小企业约定以第三方付款为付款前提的，可能直接涉及“该约定是否有效”的问题；[最高人民法院法释〔2024〕11号批复](https://www.court.gov.cn/fabu/xiangqing/441281.html)对此已有明确规定。超出这一适用范围时，仍需结合交易身份、合同性质和具体约定判断。Agent 应先把适用条件和缺少的事实问清楚，再给出修改或处理建议。

## 这些时刻，值得让 Agent-T 先看一遍

### 采购前：先把付款和验收谈清楚

供应商发来合同，你想确认付款节奏、验收安排、质保与违约责任。先整理关注项，再带着具体问题和供应商沟通。

### 租赁前：看清入住之外的退出成本

签下办公室或经营场地之前，核对押金、提前解约、维修和装修恢复等约定。除了“租多少钱”，也问清“怎么退、谁来修、离开时要承担什么”。

### 交换资料前：弄清秘密守到什么时候

签署 NDA 时，梳理保密范围、存续期限、责任和知识产权归属，明确双方的约定。

这些是使用场景示意，不代表系统能够发现其中所有风险。

## 五步开始一次审查

**上传合同 → 查看关注项 → 处理待核实 → 深入追问 → 带着建议沟通**

1. **选文件，也选视角。** 选择合同类型和代表方，上传一份合同；若 AI 对类型有不同判断，会提示你确认。
2. **逐项看清楚。** 查看核查结果、说明和摘句；接入 AI 后还可查看参考观察。
3. **处理需要确认的事。** 对证据没有闭合的问题补充说明、确认无误或提出异议，再审本条。
4. **把问题问具体。** 例如：“这条对付款有什么影响？”“请给我一个便于双方协商的改法。”
5. **核对后再使用。** 对照合同检查建议，复制需要讨论的改写稿，或导出报告交给同事。

## 现在支持什么？

| 合同类型 | 当前阅读视角 | 主要核查内容 |
|---|---|---|
| 采购合同 | 买方；未声明时按买方视角提示 | 主体、标的、付款、履行期限、违约、质保相关安排等 |
| 租赁合同 | 承租方；未声明时按承租方视角提示 | 租期、租金、押金、交付、维修、装修、提前解约等 |
| 保密协议（NDA） | 可声明披露方或接收方 | 保密范围、协议期限、保密存续期、责任、知识产权等 |

选择立场会记录审查视角，当前规则核查口径不随立场改变。采购卖方与租赁出租方视角暂不支持。

当前界面、规则包与样例主要面向中文合同。文件支持文本、Word（`.docx`）与文字版 PDF；PDF 需安装解析依赖。旧版 `.doc` 与扫描件取决于解析环境，建议先转换为 `.docx` 或可复制文字的 PDF。单份文件上限 **10 MB**，一次审查一份合同。

## 从审一份合同，到看懂一个项目

> **合同告诉我们“应该发生什么”，项目资料告诉我们“实际上发生了什么”。主动核查，就是把两者对照起来。**

今天的 Agent-T 聚焦单份合同。更长远的方向，是建立一个项目证据空间，让合同审查从签约前的一次动作，延伸到履约、验收、付款、变更和索赔的全过程。

可以把未来的分工理解为：

- **项目资料库**是一间档案室，保存主合同、补充协议、技术附件、会议纪要、送货单、验收报告、整改记录和付款资料。
- **RAG 检索**是一位熟悉档案位置的管理员，按照问题找出可能有关的原文。
- **主动核查 Agent**是一位审核人员，知道下一步该查什么，并判断证据是否完整、版本是否正确、文件之间是否矛盾。
- **证据链**是最后整理出的案卷，让每个结论都能回到具体文件、版本、页码和原文。

例如，当财务问“这笔 95% 的设备款现在能付吗”，Agent 不只重复合同中的付款条件，还应核对：

1. 最新补充协议有没有改变付款比例；
2. 验收报告是否由双方签署；
3. 整改事项是否已经关闭；
4. 发票和付款申请金额是否与最新约定一致；
5. 缺少哪些材料，导致目前还不能作出可靠判断。

如果主合同写 95%，补充协议改为 80%，验收报告缺少采购方签字，而且仍有两项整改未关闭，理想的结论应该是：

> 当前资料不足以证明“验收合格”的付款条件已经满足；最新补充协议还将本次付款比例调整为 80%。建议暂缓按 95% 支付，并补充采购方签署的验收文件及整改关闭记录。

这条证据链需要同时告诉使用者：结论来自哪份文件、哪个版本、哪一条原文，以及为什么这些材料能够支持当前判断。

| 产品阶段 | Agent-T 要解决的问题 |
|---|---|
| **现在：单份合同主动核查** | 在同一份合同中定位证据、筛出待确认事项，并在人工补充后重新核对。 |
| **继续深化：修改验证闭环** | 提供不同强度的改写方案，检查一处修改是否影响付款、违约、发票和期限等关联条款。 |
| **长期方向：项目证据空间** | 用多文档检索连接合同约定与履约事实，识别版本变化、证据冲突、材料缺失和关键期限。 |

多文档项目空间与 RAG 目前尚未实现，也不属于本轮 MVP 的现成功能。真正的目标不是“接入一个向量数据库”，而是让每一次检索都服从文件权限、版本关系和证据效力，让 Agent 在证据不足时明确说出还缺什么。

## 有依据地讨论，也保留判断的余地

Agent-T 将**规则核查结果**与**AI 参考意见**分开展示。AI 提出的候选问题需要人工确认，参考评分也不会覆盖逐条规则状态。

它适合帮你准备问题、理解约定、形成沟通草稿。当前仍处于 MVP 持续迭代阶段，可能误报、漏报或引用不准确；长合同的 AI 阅读受分段预算限制。请对照原文核实引用与改写，重要合同仍应交由专业人员复核。

### 合同数据会去哪里？

合同在你部署的服务器上解析和保存。未配置模型 Key 时，不会调用大模型；配置后，相关合同文本和问题会发送到所选模型服务商，若使用自定义网关则发送到该网关。记录默认 24 小时后不可访问，保存期限可配置，清理机制详见安装指南。

首次使用建议上传样例或脱敏合同。部署到公网、接入真实合同前，请配置访问认证与 HTTPS。
